# Rust: заключительный блок 56–60

Статус на 2026-09-24: уроки 1–55 опубликованы; 56–60 — черновики на kz/ru/en. Заключительный результат — консольный органайзер с локальным JSON-файлом, проверкой данных и отдельной восстановленной копией. Графическое окно остаётся необязательным продолжением.

| Урок | Действие ученика | Проверяемый результат |
|---:|---|---|
| 56 | Запустить независимые тесты на настоящих учебных файлах | Повреждённый JSON отвергнут, Unicode сохранён, повторное чтение не меняет данные, одинаковые ID отвергнуты |
| 57 | Проверить проект локально и отправить в учебный репозиторий | `fmt`, Clippy и тесты проходят; ученик умеет открыть результат для каждой из трёх ОС |
| 58 | Собрать исполняемый файл для своей ОС и написать инструкцию передачи | Получатель может определить версию, распаковать архив, запустить `help`; не обещаем универсальный бинарник для всех ОС |
| 59 | Самостоятельно добавить небольшую возможность к органайзеру | Требование записано до кода; есть тесты успеха и ошибки, обновлена инструкция |
| 60 | Собрать и передать полный проект | Из пустого окружения получатель может установить Rust, запустить тесты, создать задачу, закрыть программу, открыть её снова, проверить копию и восстановить данные в отдельный файл |

## Сквозная проверка перед выпуском 60

1. Проект использует `Cargo.lock` и документированную версию Rust. Данные находятся по явно указанному пути; относительный путь объяснён.
2. Отсутствующий файл означает первый запуск только для команды, которой это допустимо. Повреждённый или недоступный файл никогда не превращается в пустой список.
3. При неверной команде и ошибке файла программа пишет в stderr и возвращает ненулевой код. Обычный результат идёт в stdout.
4. Сохранение идёт через соседний временный файл. Текст курса честно ограничивает гарантии при отключении питания, переносе между файловыми системами и одновременной записи.
5. Копия проверяется перед использованием. Восстановление пишет в отдельный путь, не стирая исходный повреждённый файл и существующую цель.
6. Команды выполняются с названием задачи на казахском, русском и английском языках. Все сообщения, примеры и README подготовлены отдельно для kz/ru/en.
7. Ученик может пройти обязательное задание каждого урока без скрытого шага, увидеть ожидаемый результат и сравнить своё решение с эталоном.
8. Все три локализации проходят ручную вычитку, проверку ссылок, компиляцию и запуск примеров, тесты Cargo, CI и проверку страниц на разных экранах до публикации.
