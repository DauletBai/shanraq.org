# Курс «AI без LLM: создаем свою модель ИИ»

Статус: курс из 30 уроков завершён и опубликован на русском, казахском и английском 24 сентября 2026 года.

## Обещание читателю

За 30 уроков читатель соберёт локальную систему для коротких вопросов о вымышленном учебном клубе. Она разберёт знакомые казахские формы слов, определит запрос, найдёт утверждённый факт и вернёт ответ вместе с его источником. При нехватке данных она скажет «білмеймін» («не знаю»). Это узкая модель для проверяемой задачи, а не универсальный собеседник.

Курс ориентирован на старшеклассников и студентов. Достаточно базовых навыков Python; первые два урока дают нужное повторение. Всё запускается без GPU, платного API и постоянного доступа к сети. Интерфейс первой версии — консоль и локальные JSON-файлы; веб-интерфейс возможен после завершения ядра, но не является условием обучения.

## Что отличает курс от уже существующих

Курс Python на сайте показывает анализ данных, классическое ML и использование LLM. Здесь читатель строит *языковую систему с нуля*: описывает морфологию, собирает проверяемый смысл из текста, проектирует границы знания, измеряет ошибки. `qazaq-ir` служит примером компактного конвейера «слова → корни → допустимые окончания → признаки → JSON». `adam` — пример более крупной системы с поиском фактов, правилами и шаблонами. Учебный код создаётся отдельно и не выдаётся за полнофункциональную копию этих проектов.

## Архитектура учебного проекта

```text
Казахский вопрос, кириллица
  → разбиение на слова и проверка письма
  → словарь основ и допустимые цепочки окончаний
  → возможные разборы + пометка неопределённости
  → определение намерения и выделение сущностей
  → поиск по утверждённым фактам с идентификатором источника
  → проверка достаточности доказательства
  → один из заранее заданных ответов либо «не знаю»
```

Детерминированность означает, что одинаковые входные данные и версии правил дают одинаковый результат; она **не доказывает правильность** результата. Каждая стадия выдаёт понятную структуру: найденное, не найденное, несколько допустимых разборов. На неоднозначном входе система запрашивает уточнение или воздерживается от ответа. Неизвестный факт никогда не заполняется догадкой шаблона.

Позднее читатель добавляет маленький обучаемый классификатор для *предложения* намерения, когда правила не сработали. Классификатор не создаёт факты и не обходит проверку источника. Для него нужны независимо размеченные человеком примеры; метки, полученные только от правил, не являются независимой проверкой улучшения.

## Стек и данные

| Часть | Выбор | Причина |
|---|---|---|
| Учебное ядро | Python 3 и стандартная библиотека | Один доступный язык; прозрачные алгоритмы без скрытых библиотечных шагов |
| Правила и факты | UTF-8 JSON | Данные можно открыть и проверить глазами; версия правил фиксируется рядом с результатом |
| Проверки | `unittest`, фиксированные примеры, отдельно размеченный контрольный набор | Повторяемые проверки и честная оценка незнакомых формулировок |
| Дополнительный мост | Запуск Rust CLI `qazaq-ir` через `subprocess` | Сравнить учебный разбор с существующим проектом, не делая его обязательной зависимостью |
| Публикуемый артефакт | Локальная CLI-программа и набор данных | Полностью воспроизводимая работа на обычном компьютере |

Версию Python, лицензии примеров и точный формат наборов данных фиксируем перед написанием уроков. Для заданий используем вымышленные сведения клуба, чтобы не подменять их актуальными реальными правилами учреждения. Основной ввод — казахский текст в кириллице; латиница, смешанное письмо, опечатки и свободная беседа идут в раздел ограничений.

## Учебный стандарт

Каждый урок на русском, казахском и английском: жизненный образ → показ целого → объяснение каждого нового термина и знака → компактная опорная схема → воспроизведение по памяти → задание на новых данных → самостоятельная проверка → разбор типичной ошибки. Это применение методики Шаталова: опорный конспект служит для восстановления мысли, а не для заучивания непонятных символов. Перед выпуском блока вручную проходим задания как новичок и вычитываем все три версии, особенно естественность казахского текста.

Контрольные точки: после урока 5 читатель объясняет форму слова без кода; после 10 разбирает новые формы; после 20 отвечает только по источнику; после 25 показывает ошибки на отложенных вопросах; после 30 демонстрирует воспроизводимый проект. Переход возможен только после проверки предыдущего навыка.

## Что измеряем и чего не обещаем заранее

Число «в тысячу раз» можно писать как результат только после прямого сравнения на одинаковых запросах, оборудовании, настройках, качестве ответов и объёме результата. Отдельно измеряем размер файлов и память, задержку при холодном и тёплом запуске, расход энергии при доступности измерителя, а также полную стоимость: вычисления, разметка, сопровождение. Сравниваем с выбранной локальной и/или API-моделью, указывая её версию и цену на дату опыта. Без сопоставимой точности скорость сама по себе ничего не доказывает.

«Нет галлюцинаций» в курсе означает узкое проектное свойство: система не генерирует неподтверждённые *новые факты* и возвращает отказ, если не нашла подходящего утверждённого источника. Это не означает нулевой риск ложных ответов: ошибочный факт, неверный разбор, неудачное сопоставление и ошибка в шаблоне остаются возможными. Защита проверяется долей неверно подтверждённых ответов, а также долей честных отказов.
