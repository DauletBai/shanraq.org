# Методы: действия рядом с Task

_Лид (summary):_ **Урок 28. Создать задачу, прочитать её состояние и завершить её через методы.**

Предварительно: уроки 14, 20, 21 и 27. Если разница между `&` и `&mut` забылась, повторите [урок 21](/read/rust-21-mutable-borrow?lang=ru).

## Образ и опорная карта

У карточки задачи есть не только заполненные графы, но и действия: прочитать состояние, отметить выполнение. **Метод** — функция, связанная с типом и вызываемая через значение этого типа. Блок `impl Task { ... }` собирает такие действия рядом с описанием `Task`; `impl` означает «реализация». Образ ограничен: карточка сама ничего не делает — код метода явно выполняется при вызове.

**`struct Task` → `impl Task` → `Task::new(...)` → `task.is_done()` → `task.finish()`.** Перескажите карту. Функция `new` внутри `impl` без параметра `self` связана с типом и вызывается как `Task::new(...)`; `::` показывает путь от типа к функции, как в `String::from(...)`. Это **связанная функция**, а не метод экземпляра. Метод имеет первый параметр `self`: `&self` берёт задачу для чтения, `&mut self` — для изменения. При вызове `task.is_done()` или `task.finish()` Rust передаёт `task` как этот первый параметр автоматически.

## Читаем и меняем задачу

Сохраните прежний `src/main.rs` проекта `organizer`, замените его целиком и запустите `cargo run` рядом с `Cargo.toml`. Других файлов и зависимостей нет. Сначала предскажите результат.

`new` принимает название и минуты, создаёт `Task` с `done: false` и возвращает его. В `Task { title, minutes, done: false }` два имени без `:` — сокращённая запись полей: это `title: title, minutes: minutes`, потому что имена параметров совпадают с именами полей. Здесь переданы известные нам подходящие значения; функция пока не проверяет пользовательский ввод. `is_done` возвращает копируемый `bool` и не меняет задачу. `finish` меняет поле, поэтому требует `&mut self` и изменяемой переменной `task`.

```rust
struct Task {
    title: String,
    minutes: u32,
    done: bool,
}

impl Task {
    fn new(title: String, minutes: u32) -> Task {
        Task {
            title,
            minutes,
            done: false,
        }
    }

    fn is_done(&self) -> bool {
        self.done
    }

    fn finish(&mut self) {
        self.done = true;
    }
}

fn main() {
    let mut task = Task::new(String::from("Чтение"), 20);
    println!(
        "{}: {} мин, готово {}",
        task.title,
        task.minutes,
        task.is_done()
    );
    task.finish();
    println!("После: {}", task.is_done());
}
```
```text
Чтение: 20 мин, готово false
После: true
```

`title` передаёт владение строкой в новый экземпляр. У `finish` нет стрелки результата; значит, он возвращает `()` из урока 14. Заимствование через `&mut self` заканчивается после вызова, и `is_done` снова может читать задачу.

## Когда `&mut self` нельзя взять

Если переменная не объявлена `mut`, метод изменения не может получить изменяемую ссылку. Этот **отдельный** пример намеренно не компилируется с E0596:

<!-- error-code: E0596 -->
```rust,compile_fail
struct Task { done: bool }
impl Task {
    fn finish(&mut self) { self.done = true; }
}
fn main() {
    let task = Task { done: false };
    task.finish();
}
```

Добавление `mut` к `task` разрешит вызов. Но методы не отменяют правил владения: `&self` не меняет поля, а `&mut self` требует исключительного доступа на время вызова. `new` здесь не запрещает `0` минут. Полную проверку значений и сообщение об ошибке добавим, когда освоим `Result`.

struct Task {
    title: String,
    done: bool,
}

impl Task {
    fn new(title: String) -> Task {
        Task { title, done: false }

    fn is_done(&self) -> bool {
        self.done
    }

        self.done = true;

fn main() {
    let mut task = Task::new(String::from("Прогулка"));
