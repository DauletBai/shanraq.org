# Что такое Rust и зачем он появился

_Лид (summary):_ **Урок 1. Объяснить выбор языка без обещаний абсолютной безопасности.**


## Зачем это нужно

Представьте, что вы записали дела на листке. Чтобы узнать, сколько осталось, приходится пересчитывать их. Программа может делать это за вас. **Программа** — инструкции для компьютера; **алгоритм** — способ решения задачи по шагам. Рецепт похож на алгоритм, но человек додумывает пропущенное, а компьютеру нужны точные действия.

**Rust** — язык программирования. Разработчик пишет **исходный код**, то есть текст по правилам языка. **Компилятор** проверяет этот текст и преобразует его в программу, которую может выполнять компьютер. Образ — переводчик с проверкой правил. Граница образа: компилятор не знает, правильно ли вы задумали подсчёт дел.

## Сразу целиком

Наш путь: текст программы → проверка и сборка → запуск → результат. Между редактированием текста и запуском лежит сборка. Если вы изменили текст, старый готовый файл сам не обновился.

Пример задачи без кода: было три дела, одно закончено, осталось два. Если записать «три плюс один», программа может безупречно выполнить неправильное поручение. Поэтому понадобятся проверки результата, а не только успешная сборка.

## Почему появился Rust

Rust начал Грейдон Хоар; затем в развитии участвовала Mozilla. В браузерах и других больших программах нужны скорость, управление ресурсами и надёжность. **Память** — место для данных во время работы. Опасно читать данные, место для которых уже освобождено, или несогласованно менять общие данные. Разработчики Rust искали способ предотвращать определённые классы таких ошибок, сохраняя контроль над ресурсами.

Позже мы разберём владение: кто отвечает за данные и когда ими можно пользоваться. Пока не нужно запоминать его правила. Rust проверяет многие правила доступа к памяти ещё до запуска. Это не обещание отсутствия всех ошибок: можно неверно посчитать, потерять файл неудачным сохранением или неправильно обработать ввод.

Rust применяют для инструментов терминала, серверов, системных компонентов и устройств. Это не язык только для операционных систем. Он не обязан быть лучшим выбором для любой задачи. Наш органайзер позволит освоить язык без одновременного изучения сетевого сервера или устройства процессора.

## Опорная карта

Задача → точные действия → исходный код → компилятор → готовая программа → проверка результата. Компилятор проверяет правила языка; человек и тесты проверяют соответствие задаче.

## Разминка

1. Предскажите: заметит ли компилятор, что вместо вычитания мы хотели сложение?
2. Заполните: исходный код — это ___, готовая программа — результат ___.
3. Почините утверждение: «Если Rust собрал программу, в ней нет ошибок».

## Задание

**Обязательное.** На бумаге или в текстовом файле объясните три слова: программа, исходный код, компилятор. Затем опишите подсчёт оставшихся дел для трёх дел и одного выполненного. Ожидаемый результат: два оставшихся дела и объяснение, почему успешная сборка сама не доказывает этот результат.

**На своих данных.** Выберите другое число дел и выполненных, не больше общего числа.

## Подсказка и эталон

Сначала назовите входные данные, потом действие, потом ожидаемый ответ. Эталон: 3 − 1 = 2. Исходный код — текст инструкций; компилятор проверяет правила и преобразует его; программа выполняет написанные действия. «Собралась» означает прохождение определённых проверок, но не правильность всех решений.

Готовы дальше, если можете объяснить разницу между текстом программы и результатом её работы своими словами.
