# Модель өз дерегімізде: әр санды салыстыру

_Лид (summary):_ **Python курсының елуінші сабағы. Модельге тұрақты дереккөз идентификаторлары бар шағын кесте береміз, құрылымды тұжырым қабылдап, әр санды бастапқы жазбамен салыстырамыз. Модель сөзбен атауды ұсынады, ал тексерілген мәнді, бірлікті және жылды қорытынды мәтінге код қояды.**

## Бұл не үшін керек

49-сабақта JSON құрылымын тексердік. `{"value": 17.9}` жауабы схемаға толық сай болып, бәрібір ойдан шығарылуы мүмкін. Схема санның түрін біледі, біздің кестені білмейді.

Сондықтан әр фактіге тұрақты `source_id` береміз. Модель оны мәнмен бірге қайтарады. Код бастапқы жолды тауып, мәнді, жылды және бірлікті салыстырады. Бір өріс сәйкес келмесе, тұжырым жарияланбайды.

Модельге дайын сөйлем ішінде цифр жаздырмау одан да сенімді. Ол тек сөздік атауды береді, ал бағдарлама тексерілген сандарды пішімдейді.

## Бірден толығымен

`grounded.py` файлы алдыңғы сабақтағы келісімді жалғастырады.

```python
"""50-сабақ: модель жауабын бастапқы дерекпен салыстыру."""

import json
from decimal import Decimal

from jsonschema import Draft202012Validator

SOURCES = {
    "inflation-kz-2025": {
        "year": 2025,
        "value": Decimal("11.4"),
        "unit": "percent",
    }
}

CLAIM_SCHEMA = {
    "type": "object",
    "properties": {
        "source_id": {"type": "string"},
        "year": {"type": "integer"},
        "value": {"type": "number"},
        "unit": {"type": "string"},
        "label": {"type": "string", "minLength": 1},
    },
    "required": ["source_id", "year", "value", "unit", "label"],
    "additionalProperties": False,
}
VALIDATOR = Draft202012Validator(CLAIM_SCHEMA)


def verify_claim(raw):
    """Құрылымды, дереккөзді және әр сандық өрісті тексеру."""
    claim = json.loads(raw, parse_float=Decimal)
    VALIDATOR.validate(claim)
    source = SOURCES.get(claim["source_id"])
    if source is None:
        raise ValueError("белгісіз дереккөз")
    for field in ("year", "value", "unit"):
        if claim[field] != source[field]:
            raise ValueError(f"{field} дереккөзге сәйкес емес")
    if any(char.isdigit() for char in claim["label"]):
        raise ValueError("модель атауға сан қосты")
    return claim, source


raw = json.dumps({
    "source_id": "inflation-kz-2025",
    "year": 2025,
    "value": 11.4,
    "unit": "percent",
    "label": "Қазақстандағы инфляция",
})
claim, source = verify_claim(raw)
text = f'{claim["label"]}: {source["value"]} % ({source["year"]}).'

print("дереккөз:", claim["source_id"])
print("сан салыстырылды:", claim["value"] == source["value"])
print("бірлік салыстырылды:", claim["unit"] == source["unit"])
print("қорытынды:", text)
```

Шығыс:

```text
дереккөз: inflation-kz-2025
сан салыстырылды: True
бірлік салыстырылды: True
қорытынды: Қазақстандағы инфляция: 11.4 % (2025).
```

## Дерекке тұрақты мекенжай беру

`source_id` — бүкіл сайтқа сілтеме де, сұрыптаудан кейін өзгеретін жол нөмірі де емес. Бұл бір жазбаның тұрақты идентификаторы. Ол деректер жиынының нұсқасына, бақылау күніне және өлшем бірлігіне апаруға тиіс.

Модельге міндетке қажет жолдарды ғана беріңіз. Бұл шуды, жад шығынын және қате мән таңдау мүмкіндігін азайтады. Сұраныспен бірге жиын нұсқасын не оның цифрлық таңбасын сақтаңыз.

## `Decimal` не үшін керек

JSON бөлшекті әдетте `float` етеді. Екілік бөлшек ақша мен дәл салыстыруға қолайсыз. `json.loads(..., parse_float=Decimal)` ішіндегі `11.4` мәнін `Decimal("11.4")` мәнімен дәл салыстырылатын ондық сан етіп оқиды.

Бұл санды шын етпейді, тек ұсыну қатесін жояды. Дереккөзбен сәйкестік оның қайдан алынғанын дәлелдейді.

## Сөз бен санның міндеті бөлек

Модель `label="Инфляция 15 пайызға өсті"` десе, мәтінге жаңа сан жасырды. Әдейі қатаң `isdigit()` ережесі мұндай атауды қабылдамайды. Модель көрсеткішті атайды, код мәнді шығарады.

Цифрды тексеру редакциялық мәтінге жеткіліксіз: «инфляция төмендеді» деген қате сөйлемде сан жоқ. Сондықтан бұл сабақта тек бейтарап атауға рұқсат береміз. Өсу не төмендеуді бағдарлама екі тексерілген мәннен өзі есептеуі керек.

## Үндемей түзетпеңіз

Модельдің қате мәнін дұрысына білдірмей алмастырмаңыз. Бас тарту себебін сақтап, жаңа жауап сұраңыз немесе адамға жіберіңіз. Әйтпесе журналдағы жауап пен жарияланған мәтін екі бөлек болады.

Негізгі себептер: белгісіз `source_id`; мән, жыл не бірлік сәйкес емес; атауда цифр бар; JSON құрылымы қате.

## Тапсырма

**Міндетті.** `accept_many(raw_items, sources)` функциясын жазыңыз. `source_id` табылып, `year`, `value`, `unit` толық сәйкес келген тұжырымды ғана қабылдаңыз; атауда цифр болмасын. Қабылданған идентификаторлар мен себеп бойынша бас тарту санын қайтарыңыз.
