## Один шлюз перед публикацией

Файл `release.py` запускает обязательные команды и останавливается на первой ошибке:

```text
import subprocess
import sys

CHECKS = [
    [sys.executable, "-m", "pytest", "-q"],
    [sys.executable, "-m", "mypy", "--strict", "sholu", "main.py"],
    [sys.executable, "main.py", "--offline", "--dry-run"],
]

for command in CHECKS:
    print("+", " ".join(command), flush=True)
    subprocess.run(command, check=True)

print("READY")
```

`check=True` превращает ненулевой код возврата в остановку. Не перехватывайте эту ошибку ради зелёной надписи. Сеть не участвует в проверке публикации: кешированный снимок делает прогон повторяемым, а отдельное обновление данных имеет свои проверки.

## Публикуйте каталог, а не рабочую папку

Сначала соберите всё во временный каталог: `index.html`, встроенную картинку, CSV для проверки и `manifest.json`. В манифесте укажите время UTC, идентификаторы источников и SHA-256 каждого файла. После успешной проверки атомарно замените каталог `public` новым.

Так читатель не увидит новый HTML со старой картинкой. Неизменяемый каталог можно загрузить на любой статический хостинг. Перед внешней публикацией откройте его локально:

```console
python release.py
python -m http.server 8000 --directory public
```

Откройте `http://localhost:8000`, проверьте мобильную ширину, заголовок, дату, источники, таблицу, график и отсутствие причинных утверждений со статусом `review`.

## Финальный чек-лист

- рабочее дерево содержит только ожидаемые изменения;
- тесты и `mypy` проходят в чистой среде;
- offline dry-run ничего не записывает;
- пустой или неполный отчёт не заменяет предыдущий;
- в HTML нет секретов и персональных путей;
- дата, единицы, период и источники видны читателю;
- пользовательский текст экранирован;
- есть резервная копия предыдущего каталога или быстрый откат;
- после публикации URL возвращает `200`, а файлы совпадают с манифестом;
- журнал сообщает версию данных и результат публикации.

Публикация — это не «скопировать файл». Это переход состояния: проверенный артефакт либо заменяет предыдущий целиком, либо ничего не меняется.
