# Тип аннотациялары және `mypy`: іске қосуға дейінгі қате

_Лид (summary):_ **Python курсының елу үшінші сабағы. Дерек пішінін функция сигнатурасында сипаттап, `None` мәнін тексеру арқылы типті тарылтамыз және үйлеспейтін мәндерді бағдарлама орындалмай тұрып `mypy` көмегімен табамыз.**

## Бұл не үшін керек

Python динамикалық тіл болып қалады: аннотация орындау кезінде санның орнына жол беруге тыйым салмайды. Бірақ редактор мен `mypy` мәннің жолын алдын ала тексереді. Типтер модуль шекарасында — аргументте, қайтарылатын нәтижеде және жазба құрылымында — ерекше пайдалы.

## Бірден толығымен

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Observation:
    source_id: str
    year: int
    value: float


def latest(rows: list[Observation]) -> Observation | None:
    if not rows:
        return None
    return max(rows, key=lambda row: row.year)


def label(row: Observation | None) -> str:
    if row is None:
        return "дерек жоқ"
    return f"{row.year}: {row.value:.1f} %"


print(label(latest([Observation("cpi-kz", 2025, 11.4)])))
```

Нәтиже:

```text
2025: 11.4 %
```

`-> Observation | None` сигнатурасы бос тізім болуы мүмкін екенін ашық көрсетеді. `if row is None` тексеруінен кейін анализатор типті тарылтады: төменде `row` міндетті түрде `Observation` болады.

## `mypy` тексеруі

Курста бекітілген нұсқаны орнатып, файлды тексеріңіз:

```console
python -m pip install mypy==2.3.1
python -m mypy --strict digest.py
```

`Observation("cpi-kz", "2025", 11.4)` деп жазсаңыз, екінші аргумент `int` болуы керегін анализатор көрсетеді. Python кодты іске қоса алуы мүмкін: статикалық талдау мен орындалу уақытының айырмасы осы.

Бірден барлық кітапхананы емес, өз модульдеріңізді тексеруден бастаңыз. `pyproject.toml` файлының ықшам баптауы:

```toml
[tool.mypy]
python_version = "3.12"
strict = true
files = ["sholu", "main.py"]
```

Мұндағы нұсқа — автор компьютеріндегі кездейсоқ нұсқа емес, жоба қолдайтын ең төмен Python нұсқасы.

## Коллекциялар және түсінікті бүркеншік аттар

```python
SourceID = str
Evidence = dict[SourceID, float]

def missing(required: set[SourceID], known: Evidence) -> set[SourceID]:
    return required - known.keys()
```

Бүркеншік ат ниетті көрсетеді, бірақ `SourceID = str` жаңа тип жасамайды. Екі жолды шатастыру қауіпті болса, кейін `NewType` қолдануға болады.

## Белгісізді `Any` ішіне жасырмаңыз

`Any` мәнге арналған тексеруді өшіріп, ары қарай таралады. JSON жауабы жүйе шекарасында шынымен белгісіз: оны алдымен `object` ретінде қабылдап, құрылымын тексеріңіз, содан кейін типтелген жазба жасаңыз. Тек тыныштық үшін бүкіл сөздікті `dict[str, Any]` деп жарияламаңыз.

Аннотация ауқымды, өлшем бірлігін немесе `source_id` бар-жоғын тексермейді. Бұл — валидация мен тесттердің жұмысы. Типтер 52-сабақты толықтырады, алмастырмайды.

## Тапсырма

**Міндетті.** `latest` пен `label` функцияларын типтеңіз. Қалыпты және бос тізімді тексеріңіз. `python -m mypy --strict solution.py` пәрменін және файлдың өзін іске қосыңыз.

<!-- task out -->
```text
2025: 11.4 %
дерек жоқ
```

**Өз дерегіңізбен.** Сводканың үш ашық функциясына тип қосып, қатені `# type: ignore` қолданбай түзетіңіз.

**Қосымша.** `NewType("SourceID", str)` жасап, шатасқан идентификаторды анализатор қайдан табатынын қараңыз.
