## Ситуация и вопрос

Один и тот же расчёт нужен в команде консоли и в тестах. Если скопировать пять ветвей в оба места, после исправления одной копии другая останется старой. Вынесем правило в функцию и договоримся, что она получает и возвращает, прежде чем писать её тело.

## Новые слова без пропусков

**Функция** — именованный блок, вызываемый из разных мест. **Параметры** `done` и `days` получают значения при вызове. `return` возвращает результат и завершает эту работу; `print` лишь показывает текст на экране. **Договор функции** описывает допустимый вход и возможный выход. Здесь `done` — логическое значение, `days` — целое число либо `None`, а выход — один из `DONE`, `NO_DATE`, `OVERDUE`, `REMIND`, `NOT_YET`. **Чистая функция** не меняет файл и не читает сегодняшнюю дату скрыто: повторный вызов с теми же входами даёт тот же ответ.

## Опорный сигнал

Вход → проверка правила → изменение состояния → наблюдаемый результат. Покажите пальцем, на каком шаге программа читает данные, где сравнивает их с договором и где только сообщает результат. Если шага не видно на схеме, найдите его в коде и добавьте в собственную трассу.

## Разбираем шаг за шагом

Проведите `status(True, None)` по строкам: первая проверка возвращает `DONE`, поэтому отсутствие срока не вызывает ошибку. Для `status(False, None)` первая проверка ложна, а вторая возвращает `NO_DATE`. Для `status(False, 2)` выполняется третья подходящая ветвь и возвращается `REMIND`. Код ниже показывает эти случаи. Поменяйте местами первые две проверки: результат первой пары станет неверным; порядок входит в договор, а не является стилевой мелочью.

## Поймайте ошибку

`return` внутри цикла по списку задач остановит обработку после первой задачи, если вы поставите его слишком рано. Функция для одной задачи может возвращать сразу, а функция обхода многих должна пройти весь список. Назовите эту границу ответственности до объединения функций.
