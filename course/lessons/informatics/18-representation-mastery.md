# Контрольная точка: формат данных помощника

_Лид (summary):_ **Соберём версию 0.2 «Цифрового помощника»: формат трёх вымышленных задач, правила чтения и доказательства сохранности.**

## Где мы на карте

В прошлой части мы научились находить файлы и различать программу и данные. Теперь разберём, как данные могут передать смысл так, чтобы другой человек и другая программа прочитали их одинаково. Сначала назовите собственную догадку, затем проверьте её на числах. После проверки запишите, какую мысль пришлось изменить.

![Контрольная точка: формат данных помощника](/static/course/informatics/map-18-representation-mastery-ru.svg)

## Жизненный образ и точная модель

Представьте, что проект передали однокласснику без устных пояснений. Он должен открыть файл, увидеть три задачи, понять значения полей и восстановить данные после копирования. Если для этого нужно звонить автору, формат ещё не готов.

Формат — договорённость о структуре и смысле данных. Версия 0.2 использует UTF-8 JSON с полем version и массивом tasks. Каждая задача имеет уникальный текстовый id, title и логическое done. Три вымышленные записи: t-01 «Кітап оқу» false; t-02 «Сурет салу» true; t-03 «Есеп шығару» false. Порядок полей JSON не меняет смысла, но порядок элементов массива может быть важен для показа. Файл сохраняем без потерь; после копирования сравниваем точную копию.

## Граница образа

JSON как текст не хранит done одним физическим битом. Совпадающее количество строк не доказывает совпадение файлов. Учебная контрольная сумма из прошлого урока не служит защитой; для практической проверки точной копии используйте криптографический хеш из доверенного источника или побайтовое сравнение.

## Опорный сигнал

`три вымышленные задачи → UTF-8 JSON → открыть повторно → проверить поля → сравнить копию`

## Разобранный пример

Запишите {"version":"0.2","tasks":[{"id":"t-01","title":"Кітап оқу","done":false},{"id":"t-02","title":"Сурет салу","done":true},{"id":"t-03","title":"Есеп шығару","done":false}]}. Проверьте три разных id, три названия и ровно одно true. Сохраните как data/tasks.json в UTF-8.

## Предскажите до наблюдения

Если в копии поменять done у t-02 на false, останется ли файл корректным JSON? Да. Сохранится ли смысл исходных данных? Нет. Значит, проверка синтаксиса и проверка точности копии — разные испытания.

Не прокручивайте сразу к ответу: запишите прогноз и причину. Сравните не только итог, но и каждый промежуточный шаг. Если результат совпал случайно, повторите опыт с другими числами.

## Воспроизведите без подсказки

Закройте образец и сами опишите обязательные поля одной задачи. Затем откройте файл и проверьте, не превратили ли false в строку "false".

Закройте разобранный пример листом бумаги. Восстановите цепочку по короткому сигналу, проговорите смысл каждого перехода и лишь затем откройте пример для самопроверки. Если застряли, посмотрите только предыдущий шаг.

## Найдите и исправьте ошибку

«Файл открылся, значит данные верны». Исправьте: открыть файл — только первый шаг. Проверьте схему, три id, значения done и точность копии.

## Перенос в новую ситуацию

Передайте структуру однокласснику с другой операционной системой. Он должен открыть Ә в названии новой вымышленной задачи без искажений и объяснить UTF-8; платформа не должна менять смысл.

## Изменение проекта

Создайте data/tasks.json и FORMAT.md. В FORMAT.md опишите UTF-8, version=0.2, обязательные поля, допустимые значения done, правила уникальности id и порядок проверки. Сохраните резервную копию; сравните её с исходным файлом побайтово или через SHA-256.

## Задание

Проведите контрольную точку: 8 из 10 проверок сейчас, включая самостоятельный перенос на незнакомую запись, и 7 из 10 через семь дней. Покажите работающий файл, правила и результат сравнения. После ошибки исправьте конкретное правило и повторите равнозначный пример.

Проверьте десять пунктов: (1) UTF-8; (2) корректный JSON; (3) version = 0.2; (4) ровно три исходные задачи; (5) все id различаются; (6) title — непустой текст; (7) done — логическое значение, а не строка; (8) ровно одно true; (9) новая вымышленная запись добавляется по тем же правилам; (10) резервная копия совпадает с исходником побайтно. Пункты 9 и 10 обязательны для зачёта 8/10 сейчас и 7/10 через семь дней.

Сдавайте не фразу «понял», а проверяемое доказательство: таблицу, расчёт, файл или точный ответ с объяснением. Используйте вымышленные данные. Попросите другого человека повторить действие по вашему описанию; если ему приходится угадывать, уточните правило.

## Возврат через 1, 7 и 30 дней

Завтра без страницы восстановите три поля задачи. Через семь дней попросите другого человека добавить вымышленную запись по FORMAT.md и проверьте минимум 7 из 10 пунктов. Через месяц повторно откройте копию и объясните весь путь от символа до байта.
