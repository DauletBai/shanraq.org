# Бақылау нүктесі: көмекші деректерінің пішімі

_Лид (summary):_ **«Цифрлық көмекшінің» 0.2 нұсқасын жинаймыз: үш ойдан шығарылған тапсырманың пішімі, оқу ережесі және сақталу дәлелі.**

## Картадағы орнымыз

Енді басқа оқушы сіздің деректеріңізді сізбен сөйлеспей түсінуі керек. Ол қазақша атауды ашып, тапсырма қосып, бүлінген көшірмені байқай ала ма?

![Бақылау нүктесі: көмекші деректерінің пішімі](/static/course/informatics/map-18-representation-mastery-kz.svg)

## Өмірдегі бейне және нақты модель

Жобаны сыныптасыңызға ауызша түсіндірмей бердіңіз делік. Ол файлды ашып, үш тапсырманы көріп, өрістердің мәнін түсініп, көшіргеннен кейін деректі қалпына келтіруі керек. Авторға телефон соғу қажет болса, пішім әлі дайын емес.

Пішім — дерек құрылымы мен мағынасы туралы келісім. 0.2 нұсқасы version нысаны мен tasks массиві бар UTF-8 JSON пайдаланады. Әр тапсырмада бірегей мәтіндік id, title және логикалық done болады. Үш ойдан шығарылған жазба: t-01 «Кітап оқу» false; t-02 «Сурет салу» true; t-03 «Есеп шығару» false. JSON өрістерінің реті мағынаны өзгертпейді, ал массив элементтерінің реті көрсету үшін маңызды болуы мүмкін. Файлды шығынсыз сақтап, көшіргенде дәлдігін салыстырамыз.

## Дерек туралы келісімді қорғайық

**Формат сипаттамасы** — қандай файл мен өріс рұқсат екенін жазған келісім. **Түр** мәнді шектейді: `done` — `"true"` жолы емес, логикалық `true` не `false`; `title` — бос емес мәтін. **Идентификатор** `id` атаулары бірдей жазбаларды ажыратады. **Формат нұсқасы** `0.2` файлды қай ережемен оқу керегін көрсетеді; бұл орындалған тапсырмалар саны емес. **Кері үйлесімділік** — жаңа нұсқа бұрынғы дұрыс жазбаларды оқи алады деген айқын уәде.

Досыңызға тек `tasks.json` және `FORMAT.md` беріңіз. Ол көмексіз `Ә` әрпі бар ойдан шығарылған `t-04` тапсырмасын қосып, `done: false` таңдап, UTF-8 түрінде сақтап, неге тырнақшадағы `"false"` жарамсыз екенін түсіндірсін. Содан кейін көшірмедегі бір байтты өзгертсін: тұтастық тексерісі айырманы табуы тиіс. Адам `version` мағынасын немесе `id` ережесін болжауға мәжбүр болса, келісімді толықтырып, қайталаңыз.

8/10 үшін үш дәлел міндетті: дұрыс оқылатын файл, жаңа жазбаға білімді көшіру және әдейі бүлдірмей тұрып қор көшірмесінің түпнұсқамен теңдігі. Жеті күннен кейін басқа мысалмен тексеріңіз. Жалғыз скриншот кодтауды, түрлерді және байттардың сақталғанын дәлелдемейді.

## Ұқсатудың шекарасы

JSON мәтіні done мәнін физикалық бір битпен сақтамайды. Жол санының бірдей болуы файлдардың бірдей екенін дәлелдемейді. Өткен сабақтағы оқу қосындысы қорғаныс емес; дәл көшірмені тексеруге сенімді көзден алынған криптографиялық хеш немесе байттық салыстыру қолданыңыз.

## Сабақтың тірек сигналы

`үш ойдан шығарылған тапсырма → UTF-8 JSON → қайта ашу → өрістерді тексеру → көшірмені салыстыру`

## Талданған мысал

Мынаны жазыңыз: {"version":"0.2","tasks":[{"id":"t-01","title":"Кітап оқу","done":false},{"id":"t-02","title":"Сурет салу","done":true},{"id":"t-03","title":"Есеп шығару","done":false}]}. Үш бөлек id, үш атау және бір ғана true барын тексеріңіз. data/tasks.json файлына UTF-8-де сақтаңыз.

## Алдымен болжаңыз

Көшірмедегі t-02 үшін done мәнін false-қа ауыстырсақ, JSON дұрыс болып қала ма? Иә. Ал бастапқы дерек мағынасы сақтала ма? Жоқ. Демек синтаксис пен көшірме дәлдігі — екі бөлек сынақ.

Жауапқа бірден өтпеңіз: болжам мен себебін жазыңыз. Тек соңғы нәтижені емес, аралық қадамдарды да салыстырыңыз. Кездейсоқ дұрыс тапсаңыз, басқа сандармен қайталаңыз.

## Көмексіз жаңғыртыңыз

Үлгіні жауып, бір тапсырманың міндетті өрістерін өзіңіз сипаттаңыз. Сосын файлды ашып, false мәнін "false" мәтініне ауыстырмағаныңызды тексеріңіз.

Талданған мысалды қағазбен жабыңыз. Қысқа тірек сигнал бойынша тізбекті еске түсіріп, әр өтудің мағынасын айтыңыз. Содан кейін ғана үлгіні ашып тексеріңіз. Қиналсаңыз, тек алдыңғы қадамға қараңыз.

## Қатені тауып түзетіңіз

«Файл ашылды, демек дерек дұрыс». Түзетіңіз: ашу — алғашқы қадам ғана. Құрылымды, үш id-ді, done мәндерін және көшірме дәлдігін тексеріңіз.

## Жаңа жағдайға көшіру

Құрылымды басқа операциялық жүйедегі сыныптасқа беріңіз. Ол жаңа ойдан шығарылған тапсырмадағы Ә әрпін дұрыс ашып, UTF-8 рөлін түсіндірсін; құрылғы мағынаны өзгертпеуі тиіс.

## Жобаға енгізілетін өзгеріс

data/tasks.json және FORMAT.md жасаңыз. FORMAT.md ішіне UTF-8, version=0.2, міндетті өрістер, done мәндері, id бірегейлігі және тексеру ретін жазыңыз. Қор көшірмесін сақтап, түпнұсқамен байт бойынша не SHA-256 арқылы салыстырыңыз.

## Тапсырма

Бақылау нүктесі: қазір 10 тексерудің кемі 8-і, соның ішінде таныс емес жазбаға өз бетіңізше көшіру; жеті күннен кейін кемі 7-еуі. Файлды, ережені және салыстыру нәтижесін көрсетіңіз. Қате болса, тиісті ережені түзеп, ұқсас жаңа мысалмен қайталаңыз.

Он тармақты тексеріңіз: (1) UTF-8; (2) дұрыс JSON; (3) version = 0.2; (4) бастапқы үш тапсырма; (5) барлық id бөлек; (6) title — бос емес мәтін; (7) done — жол емес, логикалық мән; (8) бір ғана true; (9) жаңа ойдан шығарылған жазба сол ережемен қосылады; (10) қор көшірмесі түпнұсқамен байт бойынша бірдей. Қазір 8/10, жеті күннен кейін 7/10 нәтижесі үшін 9 және 10-тармақтар міндетті.

«Түсіндім» деген сөз емес, тексерілетін дәлел тапсырыңыз: кесте, есеп, файл немесе түсіндірілген нақты жауап. Ойдан шығарылған дерек пайдаланыңыз. Өзге адам сипаттамаңыз бойынша әрекетті қайталасын; болжауына тура келсе, ережені нақтылаңыз.

## 1, 7 және 30 күннен кейін қайталау

Ертең бетке қарамай тапсырманың үш өрісін еске түсіріңіз. Жеті күннен соң басқа адам FORMAT.md бойынша ойдан шығарылған жазба қоссын, кемі 7/10 тармақты тексеріңіз. Бір айдан кейін көшірмені ашып, таңбадан байтқа дейінгі жолды түсіндіріңіз.
