## Ситуация и вопрос

Вы просите библиотекаря показать список задач на 9 октября. Если сказать только «дай список», он не знает дату; если назвать дату с ошибкой, нужен понятный отказ. Браузер и сервер тоже обмениваются явными полями, а не догадками. Здесь ваш помощник наконец отвечает в браузере.

## Новые слова без пропусков

**HTTP** — правила обмена запросами и ответами между клиентом и сервером. **Метод GET** запрашивает представление данных; в нашем проекте он ничего не меняет в файле. **Путь** `/` выбирает страницу, а **параметр запроса** `today=2026-10-09` задаёт дату просмотра. **Код 200** означает успешный ответ, **400** — неверный ввод, **404** — путь не найден, **405** — метод не разрешён. **Заголовок ответа** описывает тип содержимого, например `text/html; charset=utf-8`.

## Разбираем шаг за шагом

Запустите `python3 web_assistant.py --port 8765` из `step-04`; откройте `http://127.0.0.1:8765/?lang=ru&today=2026-10-09`. Сервер читает `tasks.json`, вычисляет статусы прежней функцией и отдаёт HTML. Для трёх исходных задач на эту дату получите `REMIND`, `DONE`, `NO_DATE`. Теперь замените дату на 2026-02-29: такой календарной даты нет, поэтому сервер вернёт 400 вместо молчаливого исправления. Путь `/unknown` даст 404. Отправка POST в учебном варианте даст 405: этот выпуск только показывает данные.

## Предскажите и проверьте

Не запускайте код сразу. Выпишите точный ожидаемый результат, включая порядок строк и символы. Объясните, что код доказывает, а чего не доказывает: этот маленький пример моделирует одно правило и не создаёт настоящий интернет, TLS-сертификат или открытый сервер. Затем выполните фрагмент в каталоге `step-04` и сравните результат посимвольно. Измените один вход, сначала предскажите новый результат, потом проверьте.

```python
from urllib.parse import urlsplit
address = urlsplit("http://127.0.0.1:8765/?today=2026-10-09")
print(address.path, address.query)
```

## Ожидаемый вывод

```text
/ today=2026-10-09
```

## Поймайте ошибку

Не путайте HTTP-код ответа 200 с утверждением, что каждая задача верна; это лишь успех HTTP-обработки запроса. Не используйте GET для «отметить задачу выполненной»: ссылки и повторные запросы могут выполняться автоматически. Не показывайте трассировку внутренней ошибки или путь к файлу пользователю.
