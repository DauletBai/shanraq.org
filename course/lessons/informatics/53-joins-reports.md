# Соединение таблиц и честный отчёт

_Лид (summary):_ **Соединим две таблицы и сохраним в отчёте задачу, для которой занятий пока нет.**

## Где мы на карте

Урок 53 из 72, блок «Данные, таблицы и базы» (47–54). Мы продолжаем помощника 1.1 с тремя вымышленными задачами. В конце блока его записи будут храниться в локальном SQLite, а проверенные правила напоминаний останутся прежними.

![Соединение таблиц и честный отчёт](/static/course/informatics/map-53-joins-reports-ru.svg)

## Ситуация и вопрос

Обычное соединение показывает только `t-01` и `t-03`. Если забыть `t-02`, читатель решит, что такой задачи никогда не было. Тип соединения меняет вопрос отчёта.

## Новые слова без пропусков

**JOIN** соединяет строки по условию. **INNER JOIN** оставляет только совпадения в обеих таблицах. **LEFT JOIN** оставляет все строки левой таблицы и подставляет `NULL`, если справа совпадения нет. `COALESCE(SUM(...), 0)` показывает в отчёте ноль вместо пустого итога; подпись должна уточнить «нет записанных занятий». **Группировка** `GROUP BY` объединяет занятия по ID задачи. **Зернистость** отчёта — одна строка на задачу, не на занятие.

## Разбираем шаг за шагом

Поставьте `tasks` слева, `study_sessions` справа. Обычный INNER JOIN даёт четыре строки занятий и теряет `t-02`. LEFT JOIN даёт пять строк: четыре занятия и одну строку с задачей `t-02`, где поля занятия `NULL`. После `GROUP BY t.task_id` получаем три строки. Суммы: `t-01` — 45, `t-02` — 0, `t-03` — 25. Проверьте, что 45+0+25=70, но не делайте вывод, будто 0 означает измеренную нулевую сессию.

## Предскажите и проверьте

Измените один вход и повторите цикл «предсказать — запустить — объяснить». Пример доказывает только заявленное правило: он не превращает учебные вымышленные данные в измерение реальных людей.

## Поймайте ошибку

Если фильтровать `s.source = 'app'` в `WHERE` после LEFT JOIN, строка без занятия исчезнет: условие по `NULL` не истинно. Для отчёта «все задачи, занятия из app» фильтр по правой таблице помещают в `ON`, затем явно проверяют ожидания.
