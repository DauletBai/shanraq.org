## Ситуация и вопрос

В задаче записано «Әліппе оқу». После сохранения вместо Ә появилась непонятная последовательность, а срок `2026-10-11` кто-то назвал «два дня», не указав сегодняшнюю дату. Это две разные ошибки: потеря символов и неоговорённый отсчёт. Разберём обе на данных, которые каждый может повторить.

## Новые слова без пропусков

**Unicode** сопоставляет символам кодовые точки; это позволяет хранить Ә и A как разные буквы. **UTF-8** — способ записать такие символы байтами; при чтении и записи нужно согласовать кодировку. **Строка** `"2026-10-11"` — пока только текст. **Дата** `date` — календарный день, для которого Python умеет вычислять разность. **ISO-формат** `YYYY-MM-DD` фиксирует порядок год–месяц–день. **Часовой пояс** определяет, какой сейчас календарный день в месте пользователя. В этом опыте `today` явно равно 9 октября 2026 года; мы не притворяемся, что срок хранится в старом файле 0.2.

## Разбираем шаг за шагом

Напишите на двух карточках `2026-10-09` и `2026-10-11`, отметьте между ними два календарных перехода. В коде `date.fromisoformat` превращает каждую строку в дату, вычитание даёт `timedelta`, а `.days` — целое 2. Буква Ә выводится без замены, если исходный файл и терминал используют UTF-8. Измените срок на `2026-02-29`: Python отклонит несуществующий день, и это полезная ошибка, а не повод округлять дату.

## Предскажите и проверьте

Закройте блок с выводом. По строкам проследите значения имён и напишите точный ожидаемый текст, включая регистр и порядок строк. Только затем выполните код из каталога `step-03` командой `python3` и сравните посимвольно. Поменяйте один вход; до запуска запишите новый прогноз. Если результат отличается, найдите первую строку расхождения, а не подгоняйте ответ задним числом.

```python
from datetime import date
today = date.fromisoformat("2026-10-09")
due = date.fromisoformat("2026-10-11")
print("Әліппе оқу", (due - today).days)
```

## Ожидаемый вывод

```text
Әліппе оқу 2
```

## Поймайте ошибку

Два календарных дня не всегда означают ровно 48 часов: срок может быть утром, а сейчас вечер. Наш договор версии 0.3 использует именно календарные даты. Для будильника или секундомера понадобятся время суток и часовой пояс; не переносите сюда бездумно тот же расчёт.

## Изменение проекта

В версии 1.0 срок будет отдельным полем `due_date` со строкой ISO-даты или `null`. Не смешивайте этот формат с числом `days_to_due` из бумажных тестовых карточек: число вычисляется из даты и выбранного `today`.
