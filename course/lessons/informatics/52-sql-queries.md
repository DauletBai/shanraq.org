# SQL спрашивает данные точно

## Ситуация и вопрос

Друг просит «найди занятия по чтению». База не понимает дружеского намёка: ей нужны имя таблицы, условие и порядок ответа. Один неверный символ ID может дать пустой результат, который нужно отличить от нуля минут.

## Новые слова без пропусков

**SQL** — язык запросов к реляционным данным. `SELECT` выбирает столбцы, `FROM` называет таблицу, `WHERE` отбирает строки, `ORDER BY` задаёт порядок. `SUM` складывает, `COUNT` считает записи. **Параметр запроса** `?` принимает значение отдельно от текста SQL; такой запрос не смешивает ввод пользователя с командой. **Агрегация** сводит несколько строк к итогу. Условие `task_id = 't-01'` возвращает две записи; сумма — 45 минут.

## Разбираем шаг за шагом

Прочитайте запрос слева направо: `SELECT minutes FROM study_sessions WHERE task_id = ? ORDER BY observed_on`, параметр `t-01`. Результат — 20, затем 25. Поменяйте параметр на `t-03`: 15, затем 10. В Python передайте `(task_id,)`, а не собирайте строку SQL из пользовательского текста. Запрос `SELECT COUNT(*), SUM(minutes) ...` даст для `t-01` число записей 2 и сумму 45. Для `t-02` `COUNT(*)` равен 0, а `SUM` без строк — `NULL`; их нельзя объявлять одним и тем же.

## Предскажите и проверьте

Сначала запишите ожидаемый вывод точно, включая порядок строк. Затем выполните код из папки `step-05` и сравните посимвольно. Измените один вход и повторите цикл «предсказать — запустить — объяснить». Пример доказывает только заявленное правило: он не превращает учебные вымышленные данные в измерение реальных людей.

```python
from pathlib import Path
from tempfile import TemporaryDirectory
from data_store import create_database, connect_readonly
with TemporaryDirectory() as folder:
    db = Path(folder) / "test.db"
    create_database(db, "tasks.json", "study_sessions.csv")
    with connect_readonly(db) as connection:
        rows = connection.execute("SELECT minutes FROM study_sessions WHERE task_id = ? ORDER BY observed_on", ("t-01",)).fetchall()
    print(*(row[0] for row in rows))
```

## Ожидаемый вывод

```text
20 25
```

## Поймайте ошибку

`ORDER BY` не меняет сами минуты, только порядок строк. Отсутствие `ORDER BY` не обещает нужного порядка. Если вписать введённый текст непосредственно в SQL, специальные символы могут изменить смысл запроса; параметр отделяет данные от команды.
