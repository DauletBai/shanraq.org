# SELECT: керекті операцияны тауып, ештеңені өзгертпеу

_Лид (summary):_ **Нәтиже бағандарын таңдау, сүзу, тұрақты сұрыптау және жол санын шектеуді үйренеміз.**

## Бұл не үшін қажет

Дерекқор бәрін сақтағаны үшін емес, керегін дәл бергені үшін пайдалы: соңғы шығын, шектен үлкен сатып алу немесе бір айдың операциялары.

> **Бейне.** FROM түбіртек жәшігін үстелге қояды; WHERE керегін қалдырады; SELECT артық өрісті жабады; ORDER BY реттейді; LIMIT алғашқы бірнешеуін алады.

## Алдымен тұтас көрініс

```sql
SELECT happened_on, amount_tiyn / 100.0 AS amount_kzt, note
FROM transactions
WHERE amount_tiyn >= 1000000
ORDER BY happened_on DESC, id DESC
LIMIT 5;
```

## Талдау

Логикалық орындау FROM және WHERE бөліктерінен басталады, бірақ SELECT бірінші жазылады. SELECT * зерттеуге ыңғайлы, ал қолданба нақты бағандарды атауы керек. ORDER BY болмаса, жол ретіне кепіл жоқ; тең күнге id қосыңыз. LIKE регистрінің тәртібі әр жүйеде өзгеше.

1. SELECT неге бірінші жазылып, кейін орындалады?
2. Күндер тең болса, ретті не анықтайды?
3. SELECT * қашан тәуекел тудырады?

## Тапсырма

Қыркүйектегі ең ірі үш операцияның күнін, теңгедегі сомасын және ескертпесін шығарыңыз; тең сомада жаңасын бірінші қойыңыз.

## Жобадағы орны

Бұл үлгі операция тарихын және жаппай өзгеріс алдындағы тексеруді құрайды.

## Жауаптар

```sql
SELECT happened_on, amount_tiyn / 100.0 AS amount_kzt, note
FROM transactions
WHERE happened_on >= '2026-09-01' AND happened_on < '2026-10-01'
ORDER BY amount_tiyn DESC, happened_on DESC, id DESC
LIMIT 3;
```
