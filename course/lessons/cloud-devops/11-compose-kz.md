# Docker Compose: сервистер, желі және декларативті іске қосу

_Лид (summary):_ **Қолданба мен reverse proxy-ді бір декларациямен көтеріп, желі ішінде сервиске DNS атымен қатынаймыз.**

> Бұл сабақ нөлден басталады. Бейтаныс сөз сіздің кемшілігіңіз емес: алдымен бейне құрамыз, кейін дәл мағына беріп, содан соң қолданамыз.

## Қай жерде тұрмыз

Қысқа қайталау. Өткен сабақтың тірегі **container ауысты; volume қалды; restore деректі дәлелдеді**. Қарамай төрт буынды атаңыз, содан кейін ғана жазбамен салыстырыңыз.

## Сабақ нәтижесі

Қолданба мен reverse proxy-ді бір декларациямен көтеріп, желі ішінде сервиске DNS атымен қатынаймыз. Әр пәрмен нені тексеретінін және қандай ақауды табатынын түсіндіре алмайынша келесі сабаққа өтпеңіз.

## Алдымен таныс бейне

Оркестр әр музыкантқа бөлек қоңыраумен концерт бастамайды. Партитура қатысушы, рет және байланысты көрсетеді. Compose файлы да қолданба, proxy, желі, том және тексеруді бірге сипаттайды; service атауы ішкі мекенжай болады.

Аналогия ойды бастауға көмектеседі, бірақ технология құрылысын алмастырмайды. Төменде әр сөзді нақтылаймыз.

## Сабақтың тірек сигналы

**services + network + volumes = бір қайталанатын іске қосу**

Тізбекті солдан оңға оқыңыз. Ол «қай пәрменді жаттаймын?» емес, «келесі қадам неге алдыңғысынан шығады?» дегенге жауап береді.

## Жаңа сөздер қарапайым тілмен

- **Docker Compose** — Бір YAML сипаттамасымен байланысқан бірнеше контейнерді іске қосатын құрал.
- **Service** — Compose ішіндегі атаулы контейнер түрі және баптауы.
- **Network** — Сервистер бірін-бірі атаумен табатын виртуал желі.
- **YAML** — Шегініске сезімтал, адам оқитын дерек пішімі.

## Асықпай талдаймыз

Compose қажетті сервис, желі және томды сипаттайды. Ортақ желіде `app` аты ішкі DNS арқылы шешіледі; порт жариялау тек хост шекарасында керек. `depends_on` іске қосуды реттейді, healthcheck дайындықты дәлелдейді.

Анықтаманы сөзбе-сөз жаттамаңыз. Себептік байланысты тауып, жоғарыдағы тірекпен қосыңыз.

## Алдымен нәтижені болжаңыз

Іске қоспай тұрып қағазға жазыңыз: не өзгеруі, не сол күйде қалуы және қай output болжамды дәлелдеуі тиіс? Қате болжам да айырманы түсіндіре алсаңыз пайдалы.

## Шағын қадаммен тәжірибе

Пәрмендерді `course/cloud-devops-lab` түбірінен орындаңыз. Пәрмендер оқу ортасына арналған. Серверді не деректі өзгертетін пәрменді іске қоспас бұрын оны толық оқып, ағымдағы қалтаны тексеріңіз. Блокты мағыналық топпен орындаңыз. Әр топтан кейін тоқтап, нәтижені болжаммен салыстырыңыз.

```shell
docker compose config
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8080/healthz
docker compose logs --tail=10 app
```

[Жобаның эталон файлдары](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

### Бұл тәжірибе нақты не істейді

`config` қорытынды сипаттаманы тексереді. `up -d` ортаны соған келтіреді, `ps` күйді көрсетеді, proxy арқылы сұрау пайдаланушы жолын тексереді, `down` үдеріс пен желіні жинайды.

## Не шығуы тиіс

- Екі сервис те іске қосылған, қолданба healthy.
- Пәрмен болжамды кодпен аяқталады.
- Нәтижені таза ортада қайталауға болады.

## Тірек сызбамен тұтасты жинаңыз

![Тірек сызба 11](/static/course/cloud-devops/map-11-compose-kz.svg)

Төрт блок бойынша жүріп, бүкіл сабақты бір байланысқан әңгімемен түсіндіріңіз.

## Көмексіз жаңғыртыңыз

1. Сызбаны жауып, төрт блокты жатқа сызыңыз.
2. Әр өтуді «себебі» сөзімен түсіндіріңіз.
3. Бір жаңа терминді мәтінді қайталамай анықтаңыз.
4. Нәтижені дәлелдейтін бір сигналды атаңыз.

## Қатені тауып түзетіңіз

Қате: «`depends_on` dependency толық дайын деген сөз». Дұрысы: іске қосу реті мен дайындық бөлек; readiness жеке тексеріледі.

## Тапсырма

Енді сол мағынаны өзіңіз жинаңыз. Тірек сызбаға қарауға болады; мақсат — жады емтиханы емес, қайталанатын нәтиже.

**Міндетті.** Compose тексеріп, стекті іске қосатын, `/readyz` жауабын 30 секундтан артық күтпейтін және қатеде соңғы 50 журнал жолын шығаратын пәрмендерді жазыңыз. Тек POSIX sh пәрменін не скриптін, нақты кілт пен токенсіз жіберіңіз.

### Дайындық өлшемдері

- Әр іске қосылатын жолды түсінесіз.
- Қайталау күтілетін нәтиже не қауіпсіз түсіндірілген айырма береді.
- Output ішінде нақты key, token және password жоқ.
- Success-ті дәлелдейтін факт көрсете аласыз.

Тексеру өтпесе, күтілген және нақты нәтижені жазып, тіректің бір үзілген буынына оралып қайталаңыз. Қате оқу құқығын алып қоймайды.

**Қалауыңызша.** Бір ықтимал ақауды және оны байқайтын сигналды жазыңыз.
