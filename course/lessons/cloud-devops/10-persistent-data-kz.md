# Томдар, bind mount және деректің сақталуын дәлелдеу

_Лид (summary):_ **Күйді контейнерден шығарып, оны қайта жасап, жазбаның үдеріс ауысуынан кейін қалғанын дәлелдейміз.**

## Сабақ нәтижесі

Күйді контейнерден шығарып, оны қайта жасап, жазбаның үдеріс ауысуынан кейін қалғанын дәлелдейміз. Әр пәрмен нені тексеретінін және қандай ақауды табатынын түсіндіре алмайынша келесі сабаққа өтпеңіз.

## Бұл не үшін маңызды

Контейнер ауыстырылатын, ал күйдің өмір циклі айқын болуы керек. Named volume Docker дерегіне ыңғайлы; bind mount операторға нақты хост жолы керек кезде пайдалы. Екеуінің ешқайсысы өздігінен сақтық көшірме емес.

## Тәжірибе

Пәрмендерді `course/cloud-devops-lab` түбірінен орындаңыз. Пәрмендер оқу ортасына арналған. Серверді не деректі өзгертетін пәрменді іске қоспас бұрын оны толық оқып, ағымдағы қалтаны тексеріңіз.

```shell
docker volume create cloudlab-practice
docker run -d --name cloudlab-data -p 8080:8080 -v cloudlab-practice:/data cloudlab:lesson-09
sleep 1
curl -fsS -X POST -d 'note=survives-recreate' http://127.0.0.1:8080/notes >/dev/null
docker rm -f cloudlab-data
docker run -d --name cloudlab-data -p 8080:8080 -v cloudlab-practice:/data cloudlab:lesson-09
sleep 1
curl -fsS http://127.0.0.1:8080/ | grep survives-recreate
docker rm -f cloudlab-data
```

[Жобаның эталон файлдары](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

## Нәтижені талдаңыз

- Контейнер жойылған соң жазба қалады.
- Пәрмен болжамды кодпен аяқталады.
- Нәтижені таза ортада қайталауға болады.

## Тапсырма

**Міндетті.** Named volume жасап, уақытша контейнер арқылы файл жазып, екінші контейнер арқылы сол файлды оқитын пәрмендерді жазыңыз. Тек POSIX sh пәрменін не скриптін, нақты кілт пен токенсіз жіберіңіз.

**Қалауыңызша.** Бір ықтимал ақауды және оны байқайтын сигналды жазыңыз.
