# Бақылау, сақтық көшірме және оқу инциденті

_Лид (summary):_ **Сервис көрсеткішін анықтап, тексерілетін көшірме жасап, деректі қалпына келтіріп, кінә іздемейтін қорытынды есеп құрамыз.**

> Бұл сабақ нөлден басталады. Бейтаныс сөз сіздің кемшілігіңіз емес: алдымен бейне құрамыз, кейін дәл мағына беріп, содан соң қолданамыз.

## Қай жерде тұрмыз

Қысқа қайталау. Өткен сабақтың тірегі **Deployment Pods қалайды → Service ready Pods табады → probes traffic басқарады → rollout біртіндеп**. Қарамай төрт буынды атаңыз, содан кейін ғана жазбамен салыстырыңыз.

## Сабақ нәтижесі

Сервис көрсеткішін анықтап, тексерілетін көшірме жасап, деректі қалпына келтіріп, кінә іздемейтін қорытынды есеп құрамыз. Әр пәрмен нені тексеретінін және қандай ақауды табатынын түсіндіре алмайынша келесі сабаққа өтпеңіз.

## Алдымен таныс бейне

Үйде су өшсе, насосты қайта қосу аз. Кімге әсер еткенін біліп, ағуды тоқтатып, суды беріп, сапасын тексеріп, қайталану себебін азайту керек. Сервис инциденті де сол жолдан өтеді; кінәлі іздеу дерек жинауға кедергі.

Аналогия ойды бастауға көмектеседі, бірақ технология құрылысын алмастырмайды. Төменде әр сөзді нақтылаймыз.

## Сабақтың тірек сигналы

**detect → impact шектеу → service/data restore → verify → learn → owner+date**

Тізбекті солдан оңға оқыңыз. Ол «қай пәрменді жаттаймын?» емес, «келесі қадам неге алдыңғысынан шығады?» дегенге жауап береді.

## Жаңа сөздер қарапайым тілмен

- **Observability** — Жүйенің сыртқы сигналы арқылы жаңа сұраққа жауап алу қабілеті.
- **Metric / log / trace** — Metric уақыттағы санды, log оқиғаны, trace бір сұрау жолын көрсетеді.
- **Incident** — Қызметті нашарлатқан не қауіп төндірген жоспарсыз оқиға.
- **Restore drill** — Көшірмеден бөлек орынға қауіпсіз қалпына келтіру жаттығуы.

## Асықпай талдаймыз

Журнал жеке оқиғаға не болғанын, метрика санның уақыт бойынша өзгеруін, trace сұрау жолын көрсетеді. Сақтық көшірме тек қалпына келтірілген соң пайдалы деп саналады. Инцидент restart-пен емес, қызмет қалпына келіп, дәлел сақталып, қайталану қаупі азайғанда аяқталады.

Анықтаманы сөзбе-сөз жаттамаңыз. Себептік байланысты тауып, жоғарыдағы тірекпен қосыңыз.

## Алдымен нәтижені болжаңыз

Іске қоспай тұрып қағазға жазыңыз: не өзгеруі, не сол күйде қалуы және қай output болжамды дәлелдеуі тиіс? Қате болжам да айырманы түсіндіре алсаңыз пайдалы.

## Шағын қадаммен тәжірибе

Пәрмендерді `course/cloud-devops-lab` түбірінен орындаңыз. Пәрмендер оқу ортасына арналған. Серверді не деректі өзгертетін пәрменді іске қоспас бұрын оны толық оқып, ағымдағы қалтаны тексеріңіз. Блокты мағыналық топпен орындаңыз. Әр топтан кейін тоқтап, нәтижені болжаммен салыстырыңыз.

```shell
curl -fsS http://127.0.0.1:8080/metrics 2>/dev/null || true
mkdir -p backups
./scripts/backup.sh 2>/dev/null || true
printf 'A real drill restores into an isolated volume first.\n'
printf 'Record: detection, impact, timeline, recovery, evidence, follow-up owner and date.\n'
```

[Жобаның эталон файлдары](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

### Бұл тәжірибе нақты не істейді

Алдымен metric пен факт сақталады. Backup UTC уақыт пен checksum алады. Restore бөлек жерде жасалып, мазмұн салыстырылады. Есеп impact, timeline, шешім және келесі әрекет иесін жазады.

## Не шығуы тиіс

- Метрика пайдаланушы нәтижесімен байланысты.
- Пәрмен болжамды кодпен аяқталады.
- Нәтижені таза ортада қайталауға болады.

## Тірек сызбамен тұтасты жинаңыз

![Тірек сызба 24](/static/course/cloud-devops/map-24-incident-kz.svg)

Төрт блок бойынша жүріп, бүкіл сабақты бір байланысқан әңгімемен түсіндіріңіз.

## Көмексіз жаңғыртыңыз

1. Сызбаны жауып, төрт блокты жатқа сызыңыз.
2. Әр өтуді «себебі» сөзімен түсіндіріңіз.
3. Бір жаңа терминді мәтінді қайталамай анықтаңыз.
4. Нәтижені дәлелдейтін бір сигналды атаңыз.

## Қатені тауып түзетіңіз

Қате: «Сервис қайта 200 берсе, incident бітті». Дұрысы: user нәтижесі мен деректі тексеріп, факт сақтап, қайталануға қарсы жұмыс тағайындау керек.

## Тапсырма

Енді сол мағынаны өзіңіз жинаңыз. Тірек сызбаға қарауға болады; мақсат — жады емтиханы емес, қайталанатын нәтиже.

**Міндетті.** Каталогтың сақтық көшірмесін жасайтын POSIX sh жазыңыз: UTC уақыты бар архив, жанында SHA-256, архивті тексеру және бастапқыны жоймау. Кейін жаңа каталогқа сынақ қалпына келтіру пәрмендерін көрсетіңіз. Тек POSIX sh пәрменін не скриптін, нақты кілт пен токенсіз жіберіңіз.

### Дайындық өлшемдері

- Әр іске қосылатын жолды түсінесіз.
- Қайталау күтілетін нәтиже не қауіпсіз түсіндірілген айырма береді.
- Output ішінде нақты key, token және password жоқ.
- Success-ті дәлелдейтін факт көрсете аласыз.

Тексеру өтпесе, күтілген және нақты нәтижені жазып, тіректің бір үзілген буынына оралып қайталаңыз. Қате оқу құқығын алып қоймайды.

**Қалауыңызша.** Бір ықтимал ақауды және оны байқайтын сигналды жазыңыз.

## Ашық перспектива

Бұл соңғы сабақ. Енді бүкіл жолды қалпына келтіріңіз: өзгеріс, тексеру, шығарылым, бақылау және дәлелденген restore.
