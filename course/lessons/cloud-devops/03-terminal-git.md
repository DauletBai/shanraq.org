# Терминал и Git: воспроизводимая рабочая точка

_Лид (summary):_ **Учимся ориентироваться в каталоге, читать изменение до коммита и возвращаться к известной версии без удаления истории.**

> Этот урок начинается с нуля. Незнакомое слово здесь не считается вашим пробелом: мы сначала создадим образ, затем дадим точное значение и только потом применим его.

## Где мы находимся

Полётное повторение. В прошлом уроке была опора **🏭 железо → ☁️ ресурс → 🔁 изменение → 👀 наблюдение → 🛟 восстановление**. Не подглядывая, назовите её четыре звена и только затем сравните с записью.

## Результат урока

Учимся ориентироваться в каталоге, читать изменение до коммита и возвращаться к известной версии без удаления истории. Не переходите дальше, пока не можете объяснить, что проверяет каждая команда и какой отказ она обнаруживает.

## Сначала знакомый образ

Терминал похож на разговор с очень буквальным помощником: он не угадывает, в какой комнате вы хотели работать. Git похож на журнал мастерской: записывает контрольные состояния и позволяет увидеть, что поменялось между ними. Перед опасной командой сначала спросите «где я?» и «что изменено?».

Аналогия помогает начать рассуждение, но не заменяет устройство технологии. Ниже мы уточним каждое слово.

## Опорный сигнал урока

**📂 где я? → 📝 что изменено? → 📸 какая версия? → ✅ можно повторить**

Прочитайте цепочку слева направо. Она отвечает не на вопрос «какую команду запомнить», а на вопрос «почему следующий шаг следует из предыдущего».

## Новые слова простыми словами

- **Терминал** — Окно для текстового общения с операционной системой.
- **Shell** — Программа, которая читает команду и запускает другие программы.
- **Репозиторий** — Каталог проекта вместе с историей Git.
- **Commit и SHA** — Сохранённая точка истории и её уникальный короткий идентификатор.

## Разбираем без спешки

Инфраструктурная команда опасна, когда неизвестны каталог, версия и различие файлов. Git даёт не магическую отмену, а журнал намерений. Перед автоматизацией фиксируйте точку, смотрите diff и связывайте выпуск с конкретным commit SHA.

Сейчас не нужно запоминать формулировку дословно. Найдите в ней причинную связь и привяжите её к опорному сигналу выше.

## Сначала предскажите результат

До запуска ответьте на бумаге: что должно измениться, что должно остаться прежним и какой вывод команды подтвердит ваш прогноз? Даже неверный прогноз полезен, если после опыта вы можете объяснить расхождение.

## Опыт маленькими шагами

Выполните команды из корня `course/cloud-devops-lab`. Команды рассчитаны на учебную среду. Перед командой, меняющей сервер или данные, прочитайте её целиком и проверьте текущий каталог. Запускайте блок по одной смысловой группе. После каждой остановитесь и сопоставьте результат со своим прогнозом.

```shell
pwd
git status --short
git diff --check
git rev-parse --short HEAD
git log -1 --format='%h %cs %s'
```

[Эталонные файлы проекта](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

### Что именно делает этот опыт

`pwd` печатает текущий каталог. `status` показывает незаписанные изменения, `diff --check` ищет некоторые ошибки оформления, `rev-parse` называет точную версию, а `log` добавляет дату и смысл последнего commit.

## Что должно получиться

- `pwd` указывает на репозиторий.
- `git diff --check` не находит ошибок пробелов.
- SHA однозначно связывает код и выпуск.

Проведите пальцем или карандашом по четырём блокам и расскажите весь урок одним связным объяснением.

## Воспроизведите без подсказки

1. Закройте схему и нарисуйте четыре блока по памяти.
2. Объясните каждый переход словами «потому что».
3. Дайте определение одному новому термину, не повторяя текст дословно.
4. Назовите один сигнал, который доказывает результат.

## Найдите и исправьте ошибку

Ошибка: «Git автоматически понимает, какое изменение хорошее, и всегда безопасно отменяет всё». Исправление: Git хранит историю файлов; смысл и безопасный способ возврата выбирает человек.

## Задание

Теперь соберите тот же смысл самостоятельно. Можно смотреть на опорную схему; цель — не экзамен на память, а воспроизводимый результат.

**Обязательное.** Напишите POSIX sh-скрипт с `set -eu`, который отказывается работать вне Git-репозитория и печатает короткий SHA текущего commit. Отправьте только команды или скрипт POSIX sh без реальных ключей и токенов.

### Критерии готовности

- Вы понимаете каждую запускаемую строку.
- Повторный запуск даёт ожидаемый результат или безопасно объяснённое отличие.
- В выводе нет настоящих ключей, токенов и паролей.
- Вы можете показать факт, который подтверждает успех.

Если проверка не прошла, зафиксируйте ожидаемое и фактическое, вернитесь к одному разорванному звену опоры и повторите. Ошибка не отнимает у вас право продолжать обучение.

**По желанию.** Запишите один возможный отказ и сигнал, по которому вы его заметите.
