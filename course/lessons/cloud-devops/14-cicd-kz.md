# CI/CD кері байланыс жүйесі ретінде

_Лид (summary):_ **Pipeline-ды тәуелсіз тексерулерден құрып, үздіксіз интеграцияны жеткізу мен орналастырудан ажыратамыз.**

> Бұл сабақ нөлден басталады. Бейтаныс сөз сіздің кемшілігіңіз емес: алдымен бейне құрамыз, кейін дәл мағына беріп, содан соң қолданамыз.

## Қай жерде тұрмыз

Қысқа қайталау. Өткен сабақтың тірегі **commit → image → digest → registry → SBOM/scan → deploy**. Қарамай төрт буынды атаңыз, содан кейін ғана жазбамен салыстырыңыз.

## Сабақ нәтижесі

Pipeline-ды тәуелсіз тексерулерден құрып, үздіксіз интеграцияны жеткізу мен орналастырудан ажыратамыз. Әр пәрмен нені тексеретінін және қандай ақауды табатынын түсіндіре алмайынша келесі сабаққа өтпеңіз.

## Алдымен таныс бейне

Зауытта бөлшек әр маңызды кезеңнен кейін тексеріледі. CI өзгерістен кейін тез кері байланыс береді. Delivery тексерілген шығарылымды дайындайды, deployment жұмыс ортасын өзгертеді. Бұлар үш бөлек уәде.

Аналогия ойды бастауға көмектеседі, бірақ технология құрылысын алмастырмайды. Төменде әр сөзді нақтылаймыз.

## Сабақтың тірек сигналы

**commit → fast checks → build once → verify → deliver → deploy deliberately**

Тізбекті солдан оңға оқыңыз. Ол «қай пәрменді жаттаймын?» емес, «келесі қадам неге алдыңғысынан шығады?» дегенге жауап береді.

## Жаңа сөздер қарапайым тілмен

- **CI** — Өзгерісті жылдам тест пен тексерумен автоматты біріктіру.
- **Delivery** — Тексерілген шығарылым deploy-ға дайын күй.
- **Deployment** — Нұсқаны ортаға нақты орнату.
- **Pipeline** — Автоматты кезеңдер мен өту шарттарының тізбегі.

## Асықпай талдаймыз

CI өзгерісті біріктіруге болатынын тез хабарлайды. Continuous delivery тексерілген артефактты шығаруға дайын ұстайды; continuous deployment әр өткен өзгерісті автоматты шығарады. Сенімді қақпасыз жылдамдық ақауды тек тез жеткізеді.

Анықтаманы сөзбе-сөз жаттамаңыз. Себептік байланысты тауып, жоғарыдағы тірекпен қосыңыз.

## Алдымен нәтижені болжаңыз

Іске қоспай тұрып қағазға жазыңыз: не өзгеруі, не сол күйде қалуы және қай output болжамды дәлелдеуі тиіс? Қате болжам да айырманы түсіндіре алсаңыз пайдалы.

## Шағын қадаммен тәжірибе

Пәрмендерді `course/cloud-devops-lab` түбірінен орындаңыз. Пәрмендер оқу ортасына арналған. Серверді не деректі өзгертетін пәрменді іске қоспас бұрын оны толық оқып, ағымдағы қалтаны тексеріңіз. Блокты мағыналық топпен орындаңыз. Әр топтан кейін тоқтап, нәтижені болжаммен салыстырыңыз.

```shell
go test ./...
gofmt -l cmd internal
docker build -t cloudlab:ci .
docker run --rm -d --name cloudlab-ci -p 18080:8080 cloudlab:ci
trap 'docker rm -f cloudlab-ci >/dev/null 2>&1 || true' EXIT
sleep 1
curl -fsS http://127.0.0.1:18080/readyz
```

[Жобаның эталон файлдары](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

### Бұл тәжірибе нақты не істейді

Жергілікті script болашақ pipeline-ды қайталайды: format, test, build, image check. Әдейі шағын қате жасап және түзеткен соң іске қосыңыз — кері байланыс түсінікті болсын.

## Не шығуы тиіс

- Тексеру жылдамнан қымбатқа қарай жүреді.
- Пәрмен болжамды кодпен аяқталады.
- Нәтижені таза ортада қайталауға болады.

## Тірек сызбамен тұтасты жинаңыз

![Тірек сызба 14](/static/course/cloud-devops/map-14-cicd-kz.svg)

Төрт блок бойынша жүріп, бүкіл сабақты бір байланысқан әңгімемен түсіндіріңіз.

## Көмексіз жаңғыртыңыз

1. Сызбаны жауып, төрт блокты жатқа сызыңыз.
2. Әр өтуді «себебі» сөзімен түсіндіріңіз.
3. Бір жаңа терминді мәтінді қайталамай анықтаңыз.
4. Нәтижені дәлелдейтін бір сигналды атаңыз.

## Қатені тауып түзетіңіз

Қате: «CI/CD әр commit-ті production-ға автоматты deploy етеді». Дұрысы: deployment жиілігі мен рұқсаты — тәуекел туралы бөлек шешім.

## Тапсырма

Енді сол мағынаны өзіңіз жинаңыз. Тірек сызбаға қарауға болады; мақсат — жады емтиханы емес, қайталанатын нәтиже.

**Міндетті.** Пішім, тест, бейне жинау және smoke test кезеңдері бар POSIX sh pipeline жазыңыз. Ол алғашқы қатеде тоқтап, тест контейнерін әрқашан жоюы тиіс. Тек POSIX sh пәрменін не скриптін, нақты кілт пен токенсіз жіберіңіз.

### Дайындық өлшемдері

- Әр іске қосылатын жолды түсінесіз.
- Қайталау күтілетін нәтиже не қауіпсіз түсіндірілген айырма береді.
- Output ішінде нақты key, token және password жоқ.
- Success-ті дәлелдейтін факт көрсете аласыз.

Тексеру өтпесе, күтілген және нақты нәтижені жазып, тіректің бір үзілген буынына оралып қайталаңыз. Қате оқу құқығын алып қоймайды.

**Қалауыңызша.** Бір ықтимал ақауды және оны байқайтын сигналды жазыңыз.
