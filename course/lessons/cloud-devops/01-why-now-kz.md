# Cloud & DevOps неге қазір қажет: инфрақұрылым, рөлдер және шекаралар

_Лид (summary):_ **Дата-орталық өсімін нақты мамандық өсімінен ажыратып, cloud engineer, DevOps, platform engineer және SRE дағдыларының картасын құрамыз.**

> Бұл сабақ нөлден басталады. Бейтаныс сөз сіздің кемшілігіңіз емес: алдымен бейне құрамыз, кейін дәл мағына беріп, содан соң қолданамыз.

## Қай жерде тұрмыз

Бұл курстың алғашқы тірегі. Қазір құрал атауын жаттаудан бұрын бүкіл жолды көру маңызды.

## Сабақ нәтижесі

Дата-орталық өсімін нақты мамандық өсімінен ажыратып, cloud engineer, DevOps, platform engineer және SRE дағдыларының картасын құрамыз. Әр пәрмен нені тексеретінін және қандай ақауды табатынын түсіндіре алмайынша келесі сабаққа өтпеңіз.

## Алдымен таныс бейне

Заманауи қонақүйді елестетіңіз. Ғимарат, электр және лифт — дата-орталық тәрізді. Қосымша арқылы бөлме алу — бұлтқа ұқсайды. Қонақты орналастырып, ақауды байқап, лифтті қайта іске қосатын топ сервис эксплуатациясына ұқсайды. DevOps өзгеріс жасаған адам мен оның жұмысына жауапты адамды байланыстырады.

Аналогия ойды бастауға көмектеседі, бірақ технология құрылысын алмастырмайды. Төменде әр сөзді нақтылаймыз.

## Сабақтың тірек сигналы

**🏭 жабдық → ☁️ ресурс → 🔁 өзгеріс → 👀 бақылау → 🛟 қалпына келтіру**

Тізбекті солдан оңға оқыңыз. Ол «қай пәрменді жаттаймын?» емес, «келесі қадам неге алдыңғысынан шығады?» дегенге жауап береді.

## Жаңа сөздер қарапайым тілмен

- **Дата-орталық** — Сервер, желі, қуат және салқындату орналасқан ғимарат.
- **Бұлт** — Әр серверді сатып алмай, есептеу ресурсын бағдарлама не панель арқылы тапсыру тәсілі.
- **DevOps** — Өзгерісті шығару кезіндегі ортақ жұмыс, автоматтандыру және жылдам кері байланыс тәжірибесі.
- **SRE** — Сервис мақсаты өлшеніп, қайталанатын қол жұмысы автоматтандырылатын сенімділік тәсілі.

## Асықпай талдаймыз

DevOps — бір құрал да, бәріне жалғыз жауап беретін адам да емес. Ол автоматтандыру, қысқа кері байланыс және ортақ жауапкершілік арқылы өзгеріс тәуекелін азайтады. Дата-орталық физикалық қуат береді, бұлт оны бағдарламамен тапсырыс берілетін ресурсқа айналдырады, ал эксплуатация сервисті қолжетімді ұстайды.

Анықтаманы сөзбе-сөз жаттамаңыз. Себептік байланысты тауып, жоғарыдағы тірекпен қосыңыз.

## Алдымен нәтижені болжаңыз

Іске қоспай тұрып қағазға жазыңыз: не өзгеруі, не сол күйде қалуы және қай output болжамды дәлелдеуі тиіс? Қате болжам да айырманы түсіндіре алсаңыз пайдалы.

## Шағын қадаммен тәжірибе

Пәрмендерді `course/cloud-devops-lab` түбірінен орындаңыз. Пәрмендер оқу ортасына арналған. Серверді не деректі өзгертетін пәрменді іске қоспас бұрын оны толық оқып, ағымдағы қалтаны тексеріңіз. Блокты мағыналық топпен орындаңыз. Әр топтан кейін тоқтап, нәтижені болжаммен салыстырыңыз.

```shell
printf '%s\n' 'change -> test -> image -> deploy -> observe -> recover'
printf '%s\n' 'evidence: repeatable command, metric, backup, recovery record'
```

[Жобаның эталон файлдары](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

### Бұл тәжірибе нақты не істейді

Екі `printf` ештеңе орнатпайды. Олар курстың алғашқы картасын береді. Тізбекті солдан оңға оқып, кейін жауып, жатқа қалпына келтіріңіз.

## Не шығуы тиіс

- Тізбек өзгерістен басталып, тексерілген қалпына келтірумен аяқталады.
- Әр кезең байқалатын дәлел қалдырады.
- Курс шекарасын атай аласыз: бағдарламалық эксплуатация.

## Тірек сызбамен тұтасты жинаңыз

![Тірек сызба 1](/static/course/cloud-devops/map-01-why-now-kz.svg)

Төрт блок бойынша жүріп, бүкіл сабақты бір байланысқан әңгімемен түсіндіріңіз.

## Көмексіз жаңғыртыңыз

1. Сызбаны жауып, төрт блокты жатқа сызыңыз.
2. Әр өтуді «себебі» сөзімен түсіндіріңіз.
3. Бір жаңа терминді мәтінді қайталамай анықтаңыз.
4. Нәтижені дәлелдейтін бір сигналды атаңыз.

## Қатені тауып түзетіңіз

Қате: «DevOps — Docker, сервер және барлық ақауға жалғыз жауапты әкімші». Дұрысы: жауапкершілікті топ бөліседі, құралдар үрдісті ғана қолдайды.

## Тапсырма

Енді сол мағынаны өзіңіз жинаңыз. Тірек сызбаға қарауға болады; мақсат — жады емтиханы емес, қайталанатын нәтиже.

**Міндетті.** Шығарылым жолының алты кезеңін жеке жолға басатын және алғашқы қатеде тоқтайтын POSIX sh скриптін жазыңыз. Тек POSIX sh пәрменін не скриптін, нақты кілт пен токенсіз жіберіңіз.

### Дайындық өлшемдері

- Әр іске қосылатын жолды түсінесіз.
- Қайталау күтілетін нәтиже не қауіпсіз түсіндірілген айырма береді.
- Output ішінде нақты key, token және password жоқ.
- Success-ті дәлелдейтін факт көрсете аласыз.

Тексеру өтпесе, күтілген және нақты нәтижені жазып, тіректің бір үзілген буынына оралып қайталаңыз. Қате оқу құқығын алып қоймайды.

**Қалауыңызша.** Бір ықтимал ақауды және оны байқайтын сигналды жазыңыз.
