# Развёртывание, smoke test и проверенный rollback

_Лид (summary):_ **Выпускаем по версии, проверяем сервис снаружи и возвращаем предыдущий digest по заранее написанной процедуре.**

## Результат урока

Выпускаем по версии, проверяем сервис снаружи и возвращаем предыдущий digest по заранее написанной процедуре. Не переходите дальше, пока не можете объяснить, что проверяет каждая команда и какой отказ она обнаруживает.

## Почему это важно

Rollback должен существовать до инцидента. Он возвращает код, но не всегда возвращает совместимые данные: миграции требуют отдельного плана. После переключения проверяйте пользовательский путь и наблюдайте метрики, а не считайте успешный exit code доказательством.

## Практика

Выполните команды из корня `course/cloud-devops-lab`. Команды рассчитаны на учебную среду. Перед командой, меняющей сервер или данные, прочитайте её целиком и проверьте текущий каталог.

```shell
export CLOUDLAB_IMAGE=ghcr.io/OWNER/cloudlab:REPLACE_WITH_SHA
export CLOUDLAB_DOMAIN=cloudlab.example.com
docker compose -f compose.prod.yaml config >/tmp/cloudlab-prod.yml
grep -n 'image:[|]CLOUDLAB_ENV' /tmp/cloudlab-prod.yml
printf 'record previous digest before docker compose up -d\n'
```

[Эталонные файлы проекта](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

## Разберите результат

- Конфигурация не использует latest.
- Команда завершается предсказуемым кодом.
- Результат можно повторить на чистой среде.
