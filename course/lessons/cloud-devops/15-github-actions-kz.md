# GitHub Actions: әр өзгерісті тексеру

_Лид (summary):_ **Жергілікті тексеруді workflow-ға көшіріп, permissions бекітеміз және құпия сақтамай cache қолданамыз.**

> Бұл сабақ нөлден басталады. Бейтаныс сөз сіздің кемшілігіңіз емес: алдымен бейне құрамыз, кейін дәл мағына беріп, содан соң қолданамыз.

## Қай жерде тұрмыз

Қысқа қайталау. Өткен сабақтың тірегі **commit → fast checks → build once → verify → deliver → deploy deliberately**. Қарамай төрт буынды атаңыз, содан кейін ғана жазбамен салыстырыңыз.

## Сабақ нәтижесі

Жергілікті тексеруді workflow-ға көшіріп, permissions бекітеміз және құпия сақтамай cache қолданамыз. Әр пәрмен нені тексеретінін және қандай ақауды табатынын түсіндіре алмайынша келесі сабаққа өтпеңіз.

## Алдымен таныс бейне

Автоматты жуу көлікті датчик көргенде басталып, нақты орында бағдарлама орындайды. GitHub Actions те: event workflow бастайды, job таза runner алады, steps пәрменді ретімен орындап, нәтиже қалдырады.

Аналогия ойды бастауға көмектеседі, бірақ технология құрылысын алмастырмайды. Төменде әр сөзді нақтылаймыз.

## Сабақтың тірек сигналы

**event → workflow → job → runner → steps → evidence**

Тізбекті солдан оңға оқыңыз. Ол «қай пәрменді жаттаймын?» емес, «келесі қадам неге алдыңғысынан шығады?» дегенге жауап береді.

## Жаңа сөздер қарапайым тілмен

- **Workflow** — Автоматтандыру trigger, құқық және job жазылған YAML файл.
- **Job** — Бір runner-де орындалатын қадамдар жиыны.
- **Runner** — Job орындайтын уақытша машина не агент.
- **Permissions** — Workflow уақытша token-інің ең аз құқығы.

## Асықпай талдаймыз

Workflow — репозиторийдің орындалатын келісімі. Trigger уақытты, permissions токен құқығын, job таза машинаны, steps дәлелді анықтайды. Үшінші тарап action-ы да код; сенімді нұсқаны бекітіп, құқықты азайтыңыз.

Анықтаманы сөзбе-сөз жаттамаңыз. Себептік байланысты тауып, жоғарыдағы тірекпен қосыңыз.

## Алдымен нәтижені болжаңыз

Іске қоспай тұрып қағазға жазыңыз: не өзгеруі, не сол күйде қалуы және қай output болжамды дәлелдеуі тиіс? Қате болжам да айырманы түсіндіре алсаңыз пайдалы.

## Шағын қадаммен тәжірибе

Пәрмендерді `course/cloud-devops-lab` түбірінен орындаңыз. Пәрмендер оқу ортасына арналған. Серверді не деректі өзгертетін пәрменді іске қоспас бұрын оны толық оқып, ағымдағы қалтаны тексеріңіз. Блокты мағыналық топпен орындаңыз. Әр топтан кейін тоқтап, нәтижені болжаммен салыстырыңыз.

```shell
cp workflow.example.yml /tmp/cloudlab-workflow.yml
sed -n '1,220p' /tmp/cloudlab-workflow.yml
grep -n 'permissions:[|]go test[|]build-push-action' /tmp/cloudlab-workflow.yml
```

[Жобаның эталон файлдары](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

### Бұл тәжірибе нақты не істейді

Workflow-ды әңгіме ретінде оқыңыз: қашан, қай машинада, қандай құқықпен басталып, қандай дәлел жасайды. Пәрменді жергілікті preflight-пен салыстырыңыз.

## Не шығуы тиіс

- Workflow ішінде айқын permissions бар.
- Пәрмен болжамды кодпен аяқталады.
- Нәтижені таза ортада қайталауға болады.

## Тірек сызбамен тұтасты жинаңыз

![Тірек сызба 15](/static/course/cloud-devops/map-15-github-actions-kz.svg)

Төрт блок бойынша жүріп, бүкіл сабақты бір байланысқан әңгімемен түсіндіріңіз.

## Көмексіз жаңғыртыңыз

1. Сызбаны жауып, төрт блокты жатқа сызыңыз.
2. Әр өтуді «себебі» сөзімен түсіндіріңіз.
3. Бір жаңа терминді мәтінді қайталамай анықтаңыз.
4. Нәтижені дәлелдейтін бір сигналды атаңыз.

## Қатені тауып түзетіңіз

Қате: «Marketplace action танымал болса, қауіпсіз». Дұрысы: сыртқы action код орындайды; source тексеріп, нұсқаны бекітіп, permissions азайтыңыз.

## Тапсырма

Енді сол мағынаны өзіңіз жинаңыз. Тірек сызбаға қарауға болады; мақсат — жады емтиханы емес, қайталанатын нәтиже.

**Міндетті.** Жоба каталогына өтіп, `go test ./...` іске қосатын және пішімделмеген Go файлдарын қабылдамайтын CI қадамының shell пәрмендерін жазыңыз. Тек POSIX sh пәрменін не скриптін, нақты кілт пен токенсіз жіберіңіз.

### Дайындық өлшемдері

- Әр іске қосылатын жолды түсінесіз.
- Қайталау күтілетін нәтиже не қауіпсіз түсіндірілген айырма береді.
- Output ішінде нақты key, token және password жоқ.
- Success-ті дәлелдейтін факт көрсете аласыз.

Тексеру өтпесе, күтілген және нақты нәтижені жазып, тіректің бір үзілген буынына оралып қайталаңыз. Қате оқу құқығын алып қоймайды.

**Қалауыңызша.** Бір ықтимал ақауды және оны байқайтын сигналды жазыңыз.
