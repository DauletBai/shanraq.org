# Бір тексерілген бейнені жинау және жариялау

_Лид (summary):_ **Registry-ге тек тесттен кейін жариялап, орта арасында бір digest өткіземіз.**

> Бұл сабақ нөлден басталады. Бейтаныс сөз сіздің кемшілігіңіз емес: алдымен бейне құрамыз, кейін дәл мағына беріп, содан соң қолданамыз.

## Қай жерде тұрмыз

Қысқа қайталау. Өткен сабақтың тірегі **event → workflow → job → runner → steps → evidence**. Қарамай төрт буынды атаңыз, содан кейін ғана жазбамен салыстырыңыз.

## Сабақ нәтижесі

Registry-ге тек тесттен кейін жариялап, орта арасында бір digest өткіземіз. Әр пәрмен нені тексеретінін және қандай ақауды табатынын түсіндіре алмайынша келесі сабаққа өтпеңіз.

## Алдымен таныс бейне

Дәрінің бір партиясы тексеріліп, дәл сол партия таратылады. Әр дәріханаға қайта жасалса, бұрынғы тексеру құрамын дәлелдемейді. Образ да бір рет жиналып, орта арасында digest-пен жылжиды.

Аналогия ойды бастауға көмектеседі, бірақ технология құрылысын алмастырмайды. Төменде әр сөзді нақтылаймыз.

## Сабақтың тірек сигналы

**test once → build once → sign/scan → push digest → promote same digest**

Тізбекті солдан оңға оқыңыз. Ол «қай пәрменді жаттаймын?» емес, «келесі қадам неге алдыңғысынан шығады?» дегенге жауап береді.

## Жаңа сөздер қарапайым тілмен

- **Artifact** — Pipeline жинаған нәтиже: binary, image не package.
- **Release** — Қолдануға дайын, сәйкестендірілген өзгеріс пен артефакт жиыны.
- **Promotion** — Сол артефактты қайта жинамай келесі ортаға өткізу.
- **Provenance** — Артефакт қайдан және қандай үрдіспен алынғанын көрсететін жазба.

## Асықпай талдаймыз

Production үшін қайта жинау тесттелгеннен өзге артефакт беруі мүмкін. Бір рет жинап, тексеріп, жариялап, digest-ті орта арасында жылжыту сенімді. Registry құпиясы тек publish job-қа керек және сенімсіз fork pull request-іне берілмеуі тиіс.

Анықтаманы сөзбе-сөз жаттамаңыз. Себептік байланысты тауып, жоғарыдағы тірекпен қосыңыз.

## Алдымен нәтижені болжаңыз

Іске қоспай тұрып қағазға жазыңыз: не өзгеруі, не сол күйде қалуы және қай output болжамды дәлелдеуі тиіс? Қате болжам да айырманы түсіндіре алсаңыз пайдалы.

## Шағын қадаммен тәжірибе

Пәрмендерді `course/cloud-devops-lab` түбірінен орындаңыз. Пәрмендер оқу ортасына арналған. Серверді не деректі өзгертетін пәрменді іске қоспас бұрын оны толық оқып, ағымдағы қалтаны тексеріңіз. Блокты мағыналық топпен орындаңыз. Әр топтан кейін тоқтап, нәтижені болжаммен салыстырыңыз.

```shell
sha=$(git rev-parse --short=12 HEAD)
image=ghcr.io/OWNER/cloudlab:$sha
printf 'would publish %s\n' "$image"
printf 'production must record a sha256 digest, not latest\n'
```

[Жобаның эталон файлдары](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

### Бұл тәжірибе нақты не істейді

Тәжірибе образ жинап, commit SHA-мен байланыстырып, digest алады. Digest-ті release журналына жазыңыз. Келесі кезең сол digest-ті алуы тиіс.

## Не шығуы тиіс

- Атауда өзгермейтін нұсқа бар.
- Пәрмен болжамды кодпен аяқталады.
- Нәтижені таза ортада қайталауға болады.

## Тірек сызбамен тұтасты жинаңыз

![Тірек сызба 16](/static/course/cloud-devops/map-16-release-image-kz.svg)

Төрт блок бойынша жүріп, бүкіл сабақты бір байланысқан әңгімемен түсіндіріңіз.

## Көмексіз жаңғыртыңыз

1. Сызбаны жауып, төрт блокты жатқа сызыңыз.
2. Әр өтуді «себебі» сөзімен түсіндіріңіз.
3. Бір жаңа терминді мәтінді қайталамай анықтаңыз.
4. Нәтижені дәлелдейтін бір сигналды атаңыз.

## Қатені тауып түзетіңіз

Қате: «Сол commit-ті production-да қайта жинау бірдей». Дұрысы: dependency, base image не builder өзгеруі мүмкін; тексерілген digest-ті жылжытыңыз.

## Тапсырма

Енді сол мағынаны өзіңіз жинаңыз. Тірек сызбаға қарауға болады; мақсат — жады емтиханы емес, қайталанатын нәтиже.

**Міндетті.** `REGISTRY`, `IMAGE`, `GIT_SHA` айнымалыларын тексеріп, толық бейне атын құратын және `latest` тегін жариялаудан бас тартатын POSIX sh тексеруін жазыңыз. Тек POSIX sh пәрменін не скриптін, нақты кілт пен токенсіз жіберіңіз.

### Дайындық өлшемдері

- Әр іске қосылатын жолды түсінесіз.
- Қайталау күтілетін нәтиже не қауіпсіз түсіндірілген айырма береді.
- Output ішінде нақты key, token және password жоқ.
- Success-ті дәлелдейтін факт көрсете аласыз.

Тексеру өтпесе, күтілген және нақты нәтижені жазып, тіректің бір үзілген буынына оралып қайталаңыз. Қате оқу құқығын алып қоймайды.

**Қалауыңызша.** Бір ықтимал ақауды және оны байқайтын сигналды жазыңыз.
