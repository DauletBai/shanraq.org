# Тома, bind mounts и доказательство сохранности данных

_Лид (summary):_ **Выносим состояние из контейнера, пересоздаём его и доказываем, что заметка пережила замену процесса.**

## Результат урока

Выносим состояние из контейнера, пересоздаём его и доказываем, что заметка пережила замену процесса. Не переходите дальше, пока не можете объяснить, что проверяет каждая команда и какой отказ она обнаруживает.

## Почему это важно

Контейнер должен быть заменяемым, а состояние — иметь явный жизненный цикл. Named volume удобен для данных Docker; bind mount удобен, когда оператору нужен конкретный путь хоста. Ни один из них сам по себе не является резервной копией.

## Практика

Выполните команды из корня `course/cloud-devops-lab`. Команды рассчитаны на учебную среду. Перед командой, меняющей сервер или данные, прочитайте её целиком и проверьте текущий каталог.

```shell
docker volume create cloudlab-practice
docker run -d --name cloudlab-data -p 8080:8080 -v cloudlab-practice:/data cloudlab:lesson-09
sleep 1
curl -fsS -X POST -d 'note=survives-recreate' http://127.0.0.1:8080/notes >/dev/null
docker rm -f cloudlab-data
docker run -d --name cloudlab-data -p 8080:8080 -v cloudlab-practice:/data cloudlab:lesson-09
sleep 1
curl -fsS http://127.0.0.1:8080/ | grep survives-recreate
docker rm -f cloudlab-data
```

[Эталонные файлы проекта](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

## Разберите результат

- Заметка остаётся после удаления контейнера.
- Команда завершается предсказуемым кодом.
- Результат можно повторить на чистой среде.
