# Слои образа, теги и жизненный цикл контейнера

_Лид (summary):_ **Исследуем историю образа, фиксируем digest и различаем stop, start, remove и pull.**

> Этот урок начинается с нуля. Незнакомое слово здесь не считается вашим пробелом: мы сначала создадим образ, затем дадим точное значение и только потом применим его.

## Где мы находимся

Полётное повторение. В прошлом уроке была опора **контейнер = процесс + границы; VM = отдельная гостевая ОС**. Не подглядывая, назовите её четыре звена и только затем сравните с записью.

## Результат урока

Исследуем историю образа, фиксируем digest и различаем stop, start, remove и pull. Не переходите дальше, пока не можете объяснить, что проверяет каждая команда и какой отказ она обнаруживает.

## Сначала знакомый образ

Образ похож на запечатанный набор деталей конструктора, контейнер — уже собранная по нему модель. Тег — наклейка на коробке, которую можно переклеить. Digest — отпечаток содержимого: изменится хоть одна деталь, изменится и отпечаток.

Аналогия помогает начать рассуждение, но не заменяет устройство технологии. Ниже мы уточним каждое слово.

## Опорный сигнал урока

**Dockerfile → слои → image@digest → container → stop/remove**

Прочитайте цепочку слева направо. Она отвечает не на вопрос «какую команду запомнить», а на вопрос «почему следующий шаг следует из предыдущего».

## Новые слова простыми словами

- **Слой** — Сохранённое изменение файловой системы образа.
- **Тег** — Удобное изменяемое имя версии, например `1.0`.
- **Digest** — Криптографический идентификатор точного содержимого образа.
- **Жизненный цикл** — Создание, запуск, остановка и удаление как разные состояния.

## Разбираем без спешки

Тег — изменяемое имя, digest — идентификатор конкретного содержимого. Для воспроизводимого выпуска недостаточно написать `latest`: завтра это имя может указывать на другие байты. Жизненный цикл контейнера и образа тоже разный.

Сейчас не нужно запоминать формулировку дословно. Найдите в ней причинную связь и привяжите её к опорному сигналу выше.

## Сначала предскажите результат

До запуска ответьте на бумаге: что должно измениться, что должно остаться прежним и какой вывод команды подтвердит ваш прогноз? Даже неверный прогноз полезен, если после опыта вы можете объяснить расхождение.

## Опыт маленькими шагами

Выполните команды из корня `course/cloud-devops-lab`. Команды рассчитаны на учебную среду. Перед командой, меняющей сервер или данные, прочитайте её целиком и проверьте текущий каталог. Запускайте блок по одной смысловой группе. После каждой остановитесь и сопоставьте результат со своим прогнозом.

```shell
docker pull alpine:3.23
docker image inspect alpine:3.23 --format '{{index .RepoDigests 0}}'
docker history alpine:3.23
docker create --name cloudlab-inspect alpine:3.23 true
docker start -a cloudlab-inspect
docker rm cloudlab-inspect
```

[Эталонные файлы проекта](https://github.com/DauletBai/shanraq.org/tree/main/course/cloud-devops-lab).

### Что именно делает этот опыт

`image history` показывает слои, `inspect` — точный digest, а `run`, `stop`, `start`, `rm` дают почувствовать разницу между образом и экземпляром. После `stop` контейнер существует; после `rm` — нет.

## Что должно получиться

- Digest содержит sha256.
- Команда завершается предсказуемым кодом.
- Результат можно повторить на чистой среде.

## Найдите и исправьте ошибку

Ошибка: «Тег `latest` всегда означает самый новый и неизменный образ». Исправление: это обычная перемещаемая метка; точность даёт digest.

## Задание

Теперь соберите тот же смысл самостоятельно. Можно смотреть на опорную схему; цель — не экзамен на память, а воспроизводимый результат.

**Обязательное.** Напишите команды, которые получают образ, сохраняют его первый RepoDigest в переменную и отказываются продолжать, если digest пуст. Отправьте только команды или скрипт POSIX sh без реальных ключей и токенов.

### Критерии готовности

- Вы понимаете каждую запускаемую строку.
- Повторный запуск даёт ожидаемый результат или безопасно объяснённое отличие.
- В выводе нет настоящих ключей, токенов и паролей.
- Вы можете показать факт, который подтверждает успех.

Если проверка не прошла, зафиксируйте ожидаемое и фактическое, вернитесь к одному разорванному звену опоры и повторите. Ошибка не отнимает у вас право продолжать обучение.
